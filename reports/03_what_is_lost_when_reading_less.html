03 · 少看历史会丢掉什么：四种读取方式在真实问题上的质量对照¶

模型收到一份含“编号→四位值”记录的资料，再回答指定编号的值。例如本课 T1-2K-00 的目标记录是 1563 → 8422，问题要求只输出 8422，不能复述 1563。T1 每题问一条记录，T2 按指定顺序问两条记录；2K/8K 指资料约 2048/8192 token。

这次让冻结的 Qwen3-0.6B 先完整处理资料，再从问题开始比较不同读取方式。A 读全部历史；其余方法都必留开头 4 个和最近 64 个位置，再从其余位置中取相同数量：

方法 额外位置怎样选
B 近期窗口 取剩余位置中最近的那些
C 均匀随机 在剩余位置中均匀抽样，每层每组每步推进随机流
D0 未训练索引 当前查询和历史键经随机初始化的索引参数打分，取最高分的位置

文中把每步必留的首 4 个和最近 64 个位置合称 F。额外名额在输入第一个问题 token 时确定：当时可读位置数乘 ρ 后取整，本课分别使用 ρ=1/32 和 1/8；以后名额不再随回答变长。F 之外的可选位置称候选，它们的数量记为 M，本步实际选中的候选数记为 k。因此后面的 k/M 说的是“从剩余位置中抽了多少”，不包含 F；第 2 节用一份真实资料逐步算出这些数。

这里的名额和读取数均指本步某一层、某一个 KV 组；同组查询头共用名单。不同层或不同组的额外名单可以不同，因此这个数不是整个模型所有名单合并去重后的 token 数。

C 随机选择位置，D0 随机初始化参数。 D0 的名单仍取决于输入内容，二者是不同对照。各方法独立处理问题和自己生成的回答；具体的缓存与名额过程在第 2 节用这份资料展开。

本课对应 G2-lite：小规模任务质量对照，48 份探索资料；第二课的真实模型测速称 G1b，没有稳定达到 10% 收益门槛。这里单独检查回答质量，不把探索样本外推成总体能力。记录来自 Mac M4 Max / MPS；默认只读记录和执行随机小模型的 CPU 检查。

数据版本。 v1 是早期密集记录表；正式 v2 用 16 条记录穿插填充句；v3 后来修正 C 的随机条件，尚未用于新的这组模型运行。旧 C 改写同时改变了资料与随机名单，不能当作单变量证据。冻结主表仍使用原 v2 记录。

1. 四种读取方式的正式代码与契约¶

运行前的预测（本项目的预测卡片 reports/cards/G2lite_mac_m4max.md）：B、C、D0 在同一 ρ 下读取数相同、都包含 F；全选时三者退化为 A；B 的额外行恰为最近的 k 个候选；C 的抽取由种子决定且回退重放不变；B、C 不做 Q/K 内容打分；C 用 CPU 随机优先级的 top-k 实现均匀抽样。下面并排打印三个名单生成函数与共用的取行函数，再用两层随机小模型检查三件具体的事：

  • 输入 100 个 token 建缓存，再输入一个新 token。此时共 101 个合法位置，首部/近期必留 68 个，额外名额为 round(101/8)=13，总读取数为 81。检查 B/C/D0 是否按同一规则分配这 81 个位置，并查看各自的额外名单。
  • 把额外名额给足，让每种方法读齐全部 101 个位置，再与完整 A 比较输出。这叫“全选”检查。
  • 在已经算好的缓存中，把 B 或 C 没选中的行改成 NaN，回退一步并重算同一个输入。若少读方法确实没取这些行，输出应保持不变；A 读到这些行则会出现 NaN。这叫“污染未选行”，改的是缓存数组，不是原资料文字。

这几项检查验证程序是否按指定规则读取；后面的真实问答才检查这些规则是否保住能力。

def select_rows_kernel(u, zT, fixed_rows, off_lo, lo: int, hi: int, k: int) -> torch.Tensor:
    """D0: score the candidate columns once, top-k once, merge with the fixed rows. Returns flat row ids [B*G*S]."""
    B, G = fixed_rows.shape[:2]
    if k <= 0:
        return fixed_rows.reshape(-1)
    scores = candidate_scores(u, zT, lo, hi)                       # [B,G,1,M]
    top = torch.topk(scores, k, dim=-1).indices.view(B, G, k)      # the only top-k, over the candidate domain
    return torch.cat([fixed_rows, top + off_lo], dim=-1).view(-1)
def select_rows_recent(fixed_rows, off_lo, lo: int, hi: int, k: int) -> torch.Tensor:
    """B: the k most recent candidate positions [hi-k, hi) merged with the fixed rows. Same F and count as D0.

    Candidate-relative index i in [0, hi-lo) maps to row off_lo + i, exactly as the top-k indices do in
    `select_rows_kernel`; nothing is scored, nothing is renumbered.
    """
    B, G = fixed_rows.shape[:2]
    if k <= 0:
        return fixed_rows.reshape(-1)
    M = hi - lo
    if k > M:
        raise ValueError(f"k={k} exceeds the candidate count {M}")
    rel = torch.arange(M - k, M, device=fixed_rows.device, dtype=torch.long).view(1, 1, k).expand(B, G, k)
    return torch.cat([fixed_rows, rel + off_lo], dim=-1).view(-1)
def select_rows_uniform(fixed_rows, off_lo, lo: int, hi: int, k: int, *, rng) -> torch.Tensor:
    """C: k candidate positions drawn uniformly without replacement, independently per (batch, group), merged with F.

    `rng` is a numpy Generator (numpy.random.default_rng seeded from (uniform_seed, request, step) by the caller); the
    draw is the top-k of i.i.d. float64 uniforms, i.e. a uniformly random k-subset. The layers of one step consume the
    same generator in order, so a step replayed after a rollback draws the same rows. Not a learned choice.
    """
    import numpy as np  # local import: the package stays importable without numpy
    B, G = fixed_rows.shape[:2]
    if k <= 0:
        return fixed_rows.reshape(-1)
    M = hi - lo
    if k > M:
        raise ValueError(f"k={k} exceeds the candidate count {M}")
    u = torch.from_numpy(rng.random((B, G, M), dtype=np.float64))                # CPU, deterministic given the generator state
    rel = torch.topk(u, k, dim=-1).indices.to(fixed_rows.device)               # [B,G,k] candidate-relative
    return torch.cat([fixed_rows, rel + off_lo], dim=-1).view(-1)
def gathered_decode_step_kernel(q_main, k_cache, v_cache, rows, selected_count: int, *, scale=None, backend="sdpa"):
    """Read exactly the listed rows (flat ids into the flattened [B*G*C, d] cache) and attend over them.

    The shared tail of every selective read: D0's rows come from `select_rows_kernel`, B's from `select_rows_recent`,
    C's from `select_rows_uniform`. Two flattened index_selects (K, V), then subset attention; no torch.gather.
    """

        raise ValueError("a decode step takes exactly one new query position")

    v_sub = flatten_cache(v_cache).index_select(0, rows).view(B, G, selected_count, d)
    return subset_attention(q_main, k_sub, v_sub, scale=scale, backend=backend)

2. 一份资料怎样变成回答¶

本实验先把聊天模板头、资料表头、记录和填充文字送入模型，用完整注意力建立资料缓存。到这里还没有输入问题。 随后各方法取得各自的前缀缓存副本，从问题第一个 token 起独立推进：读自己的历史 K/V，写入自己算出的新 K/V；生成时把自己选出的 token 再送回。

问题后面还有哪些输入？ 在 T1-2K-00 中，问句“问题：编号 1563 对应的数值是多少？只输出该编号对应的四位数值，不要输出编号。”占 26 个 token；聊天模板随后追加以下字符串，另占 9 个 token（下面用 \n 显示实际换行）：

<|im_end|>\n<|im_start|>assistant\n<think>\n\n</think>\n\n

所以问题加模板后缀共 35 个 token。这里空的 <think>…</think> 是模板预先加入的输入，不是模型生成的思考文本。处理完末尾的 \n\n（一个 token）后，模型才预测首个答案 token。 下文“首个答案预测处”都指这个位置，不是问句句号所在的位置。前缀的 token 位置也从聊天模板开头计算；本例首 4 个 token 是 <|im_start|>、user、换行和“下面”，并不是四条资料记录。

代码把这个顺序命名为 document_dense_then_sparse。问题和模板尾部逐 token 处理；随后贪心生成，最多 64 个新 token，遇 EOS 停止。改写资料后，另做一次完整 Prefill，不沿用原资料的缓存。

怎样判回答。 取回答最前面的一个（T1）或两个（T2）独立四位数，与目标按顺序比较，字段为 exact_match。若先输出问题编号，即使后面再给正确值也判错；这种复述编号的错误叫“编号回声”。另外记录整段是否包含目标、提取数量是否不足、是否达到长度上限，它们不替代主评分。

资料 ID T1-2K-00 用于找到这一份输入；问题中的 1563 是这份资料内的记录编号。目标放在资料的不同部分，保存标签为 front（前部）、middle（中部）、back_near（距资料尾约 30—70 token）、back_far（约 150—250 token）。下面直接显示真实 ID 和对应记录，完整资料列表可展开查看。

def score_answer(task: str, targets, text: str, *, truncated: bool) -> dict:
    """Exact match = the first len(targets) standalone four-digit numbers equal the targets in order.

    Also reported: per-item correctness, whether every target appears anywhere (any order), whether a two-item answer is
    exactly the targets swapped, format_error (fewer numbers than required) and the truncation flag passed by the caller.
    """
    targets = [str(t) for t in targets]
    need = len(targets)
    if (task == "T1" and need != 1) or (task == "T2" and need != 2):
        raise ValueError(f"{task} expects {1 if task == 'T1' else 2} target(s), got {need}")
    numbers = extract_numbers(text)
    predicted = numbers[:need]
    return {
        "numbers": numbers,
        "predicted": predicted,
        "exact_match": predicted == targets,
        "item_correct": [i < len(predicted) and predicted[i] == t for i, t in enumerate(targets)],
        "targets_present_any_order": all(t in numbers for t in targets),
        "order_swapped": need == 2 and len(predicted) == 2 and predicted == list(reversed(targets)),
        "format_error": len(numbers) < need,
        "truncated": bool(truncated),
        "text": clean_text(text),
    }

def uniform_seed_for(cfg: dict, doc: dict) -> int:
    """Hold C's external randomness constant across rewrites of one document.

The selector still keys its stream by (seed, request counter, step), so matching
selections also requires matching candidate domains and k. D0 does not use this
seed: it continues to score the changed inputs with its fixed indexer parameters.
    """
    identity = doc.get("parent_doc_id") or doc["doc_id"]
    return int(cfg["seeds"]["uniform_base"]) + int(hashlib.sha256(identity.encode("utf-8")).hexdigest()[:8], 16) % (1 << 20)
