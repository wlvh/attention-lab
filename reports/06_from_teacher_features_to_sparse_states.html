实验课 06：把学到的选位规则放回真实推理¶

本课对应 G3c：训练后索引器接入与状态对照。此前 G3a（第四课）训练一层，G3b-lite（第五课）提供全部 28 层参数；本课检查索引器进入自己的稀疏路径后，输入和读出怎样偏离完整路径。

A 为全层完整读取；D-one 只让第 14 层用训练后索引器少读；D0 全层用初始参数少读；D 全层用训练后参数少读。主体与索引参数都固定，使用 4 份已分析过的开发资料。

配置仍是 P0（索引用主 RoPE 前 Q/K、索引空间不额外旋转）、r=32、ρ=1/8；F=首4∪近64，候选名额 k0=min(round(ρ*N0), 起始候选数) 由请求起始合法长度 N0 固定，后续按本步候选数裁剪。默认只读保存记录，不运行模型。

1. 比较同一输入，先分离状态变化¶

各方法从同一份资料重新完整 Prefill，分别保存主 K/V。之后输入相同的问题，再输入 A 预先产生的同一串 16 个 token；即使遇 EOS 仍输入满 16 步。这叫本课的控制序列，只用于对齐计算位置，不计答题成绩。每条路径都维护自己的后缀缓存，不借用 A 后来计算的 K/V。

记录中的 q/k 取自每层 q_norm/k_norm 的输出，位于 RoPE 和转置之前；单 token 时形状为 [1,1,16,128] / [1,1,8,128]。attention_output 取 o_proj 的输入 [1,1,2048]。代码分别展平这些向量再逐层比较，图横轴是层数。

资料仍是 T1：按编号返回一个四位值，如 G3a-T1-2K-48 表示旧单层阶段的第 48 份约 2K 资料。输出 controlled_not_quality 标记这条延续输入不能当作独立回答。

2. 参数固定，还必须保证缓存属于这份参数¶

z=Wk·k_pre依赖索引参数。更换参数后直接使用旧z，会让查询和历史索引处于不同规则下。本轮加载文件先验hash和形状，缓存绑定参数身份，每次写入前检查；主K/V是bf16，z与索引投影为fp32。

下面展示正式运行的同一实现。默认阅读只展示源码，不建立真实模型。

FrozenBank 是本项目装载各层固定索引参数的对象。缓存“绑定参数身份”意味着加载的文件、形状和参数版本必须对应；更换 Wk 后不能继续使用旧 z。

class FrozenBank:
    def __init__(self, indexes, *, identity):
        self.indexes = list(indexes)
        self.identity = identity
        self._objects = tuple(id(x) for x in self.indexes)

    def guard(self, state):
        if tuple(id(x) for x in state.indexers) != self._objects:
            raise RuntimeError("state index bank changed")
        for index in self.indexes:
            index.verify()
            if index.wk.device != state.cache.device:
                raise RuntimeError("index/cache devices differ")
        cache = state.cache
        if not cache.has_index or cache.index_dtype != torch.float32:
            raise RuntimeError("bank requires a float32 index cache")
        if cache.valid_length and getattr(cache,"index_identity",None) != self.identity:
            raise RuntimeError("prefix index cache belongs to different parameter identity")
        cache.index_identity = self.identity

3. 同一集合也可能有不同的有限精度计算顺序¶

初次全选检查失败：按分数排列的集合与A的原位置排列具有相同数学含义，bf16实际加总次序却不同。首次差异在第14层读出后出现，随后可能传播。记录保留，没有放宽容差。

一次修复：本轮所有稀疏方法选位后按原位置升序，再实际gather和主注意力。集合、预算和选择分数保持不变。修后单层/全层全选都要通过；这不是学习带来的准确率改善。

这里的全选是让候选名额覆盖所有合法位置，仍走实际 gather 和主注意力路径。表中 steps 是比较的输入步数，max_abs_logits/max_relative_logits/argmax_agreement 分别记录最大绝对分数差、最大相对分数差与选中 token 一致率。

4. 从第几层开始，输入已经不同？¶

下面只看问题最后一token，即首个答案预测前的位置。D-one前14层的Q与A相同：第14层的新信息先出现在注意力读出，下一层才改变Q。D在第一层就少读，因此第二层起Q已经可能不同。

相对L2先逐资料计算，再平均4份。它是各自真实状态间的差异，不能和G3b的同特征局部误差当成同一指标，更不能直接换算为准确率损失。

表中的 first_answer_prediction 是问题最后一个 token 之后，last_controlled_step 是第 16 个控制 token 之后。相对 L2 的参照和分母都来自同一步 A；第五课则给方法同一份完整路径 Q/K/V，两个指标的实验条件不同。

5. 可以推出什么，下一步还缺什么？¶

D比D0更接近A，是这4份开发资料、当前位置的描述；D-one与D也不能只用最终分数代替逐层证据。控制输入保证两条路径读到相同token，却消除了自由生成的分叉，因此argmax相同率不等于答题正确率。

下一步比较完整读取 A、近期窗口 B、均匀随机 C、初始索引 D0、训练后索引 D 各自自由生成，并保留A答错、D改善与D仍失败的题。先前冻结的新32份资料只在下一阶段评分，不据结果重新调ρ、改提示或追加训练。

这个新题质量与成本阶段叫 G4-lite，已完成的结果见第七课。本课账单里的旧 G3a 是单层训练，共享预算则累计第五至七课实际运行。
