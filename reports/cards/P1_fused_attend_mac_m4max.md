## 问题与执行前预测

**问题。** D 链的最后一段——按行表取 K、取 V、对子集做注意力（PyTorch 路径是两次拉平 `index_select` 加一次 SDPA，三次核调用）——做成按行表直接读缓存的 Metal 核，S = 1076 时每层能否 ≤ 60 µs，且满足 `dense_mask_reference` 的契约。

**设置。** 随机张量、bf16、B = 1、G = 8、h = 2、d = 128；主 K/V 缓存容量 C = N0 + 128，N0 ∈ {8192, 16384, 32256}；行表 = 固定集（首 4 ∪ 近 64）∪ 候选域里随机抽的 k 个位置，k 按 ρ = 1/32 的规则（256 / 512 / 1008），S = 324 / 580 / 1076；28 层轮换；预热 20、正式 50，每 pass 前后同步；每策略正序与反序各一次取较慢者；两个独立进程。对照 `pytorch_gather_sdpa`（G1a 路径）；上下文 `pytorch_full_sdpa`（A 读全部 L 个位置，不参与门槛）。融合核的分区数 P ∈ {1, 2, 4, 8}（P > 1 时加一个合并核）都测，门槛取最优变体。

**预测的依据。** G1a 分段计时（bf16、32K、ρ = 1/32）：取 K + V 约 30 µs，子集注意力 14 到 30 µs；G1a 的 D_read 链比分段之和高。字节：S 行 × 256 B × (K + V) × 8 组 = 4.4 MB（S = 1076），按 P0 实测的 236 GB/s 是 19 µs；但这是按名单的分散读取（每行 256 B 一段），不是连续扫描，有效带宽会更低。两个查询头共用同一次 K/V 读取（GQA），字节不随 h 增长。

**预测。**

| 项 | S = 324（8K） | S = 580（16K） | S = 1076（32K） |
|---|---:|---:|---:|
| `pytorch_gather_sdpa` µs/层 | 35–50 | 40–60 | 50–75 |
| 最优融合变体 µs/层 | 20–35 | 25–40 | **30–55** |
| 最优 / pytorch_gather_sdpa（32K） | | | 0.50–0.80 |

- S = 1076 处最优变体 ≤ 60 µs 的把握六成五。分散读取的有效带宽估 100 到 200 GB/s（4.4 MB 对应 22 到 44 µs），加启动与合并核 8 到 15 µs。
- 分区数：P = 1（每组一个线程组、8 个 simdgroup 各串行约 135 行）受访存延迟限制，预计 60 到 120 µs；P = 4 到 8 最优；P = 8 多一个合并核但在飞字节最多。
- 数值：fp32 输出对 CPU float32 参照 max|Δ| ≤ 1e-5（在线 softmax 的 fp32 累加与 Metal `exp` 的差别在 1e-7 量级）；PyTorch 路径的 bf16 输出对同一参照约 2e-3 到 8e-3；bf16 输出与 fp32 输出的 RNE 舍入 ≥ 99% 逐位相同，其余差 1 ulp。
- 契约：毒化未入选行后输出逐位不变；乱序行表与有序行表结果在 1e-5 内；S 为 5、323、1077 等边界正确。
- 若通过，对整模型的含义（估算）：P0 + P1 把 D 链里的打分段与取行注意力段从约 100 + 60 µs 压到约 70 + 45 µs，剩余的 top-k 与行号装配（约 60 到 80 µs）要靠 P2；D 链每层约 340 → 约 260 µs，32K 整步 D/A 约 0.93 → 0.83；三段都融合后才可能到范围说明里的 0.65 到 0.75。
