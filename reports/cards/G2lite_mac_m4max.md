## 问题与执行前预测

**三个问题。** (1) 基线可用性：Qwen3-0.6B（bf16、MPS、贪心、≤ 64 新 token）用完整读取 A 在 T1 / T2 × 2K / 8K 四个格子里的完整匹配率是否 ≥ 80%（小样本可用性检查，不是质量结论）。(2) 少读丢什么：B（近期窗口）、C（均匀随机）、D0（未训练索引）在**相同 F 与相同名额**下各自错在哪里；错误是否与"被查询记录相对窗口 / 被选位置的关系"对应。(3) 反事实：只改被查询记录的值，答案是否跟着改；只改一条无关记录，答案是否不变；把记录移到窗口内后 B 是否变对。

**设置（由数据生成器在运行前确定，不含模型）。** 记录表每行"编号 XXXX：YYYY"恰为 12 个 token（Qwen3 分词器逐位切数字）。2K：169 条记录，共享前缀 2049 token；8K：681 条，前缀 8193 token。问题与模板尾部：T1 27 token，T2 48 token。目标桶：front（记录序号的 2%–10%）、middle（45%–55%）、back_near（倒数第 3–5 条，记录末端距前缀末尾 37–61 token）、back_far（倒数第 13–20 条，157–241 token）。T1 每格 4 front + 4 middle + 2 back_near + 2 back_far；T2 每格两条记录成对（front/back_near ×2、front/back_far ×2、front/middle ×4、middle/back_near ×2、middle/back_far ×2），偶数号按位置升序问、奇数号降序问。数据种子 20261017，索引器种子 0（与 G1b 相同的随机 GroupedIndexer），均匀随机种子由 doc_id 派生，全部写入配置与 manifest。

**名额（由规则推出，不是预测）。** 请求起始合法长度 N0 = 前缀 + 1：2K 为 2050，8K 为 8194。k0 = round(ρ·N0)：2K 为 64（ρ = 1/32）/ 256（1/8），8K 为 256 / 1024；实际读取数 68 + k0 = 132 / 324（2K）、324 / 1092（8K），占合法长度 6.4% / 15.8%、4.0% / 13.3%。B 的窗口是首 4 ∪ 最近 64 + k0 个位置，在生成第一个答案 token 的那一步，窗口里属于资料的 token 数为 64 + k0 − Q：T1 101 / 293（2K）、293 / 1061（8K）；T2 83 / 275 / 275 / 1043。于是按几何：**back_near 在所有四个设置下都在 B 的窗口内，back_far 只在 2K · ρ = 1/32 之外的三个设置内，front 与 middle 永远在窗口外**。固定集合 F 的近 64 在那一步只覆盖资料末尾约 37（T1）/ 16（T2）个 token，即最后 1–3 条记录，**不含任何目标**；因此 C 与 D0 不能靠 F 拿到答案。

**预测 1：基线。** T1-2K 的 A 完整匹配 10–12 / 12（≥ 80% 的把握八成）；T2-2K 7–11 / 12（过线把握五成）；T1-8K 6–11 / 12（过线把握四成）；T2-8K 3–9 / 12（过线把握两成）。主情景（五成）：T1 两档可用、T2 只在 2K 可用；替代情景 A（三成）：T1-8K 也不可用，只在 2K 研究机制；替代情景 B（两成）：四格全部可用。A 的错误形态预测：答成相邻记录（位置相近）或同编号前缀相近记录的值为主，其次是先复述编号再给值（按冻结规则算错，另列 `targets_present_any_order`），格式错误（没有四位数）≤ 1 份，截断（64 token 内无 EOS）≤ 1 份。T2 的错误里"两值都对但顺序反"≤ 2 份。若某格基线不足，预登记的唯一一次提示修正是：在问题末尾加一个格式示例（如"例如：1234"），不改资料、不改任务、不改模型与样本量；修正前后的结果都保留。

**预测 2：B（近期窗口）由几何决定。** B 对当且仅当被查询记录在窗口内（模型从别处取得答案的可能性视为很小）。T1：front / middle 全错（预计 ≤ 1 / 8 碰对），back_near 全对（与 A 同），back_far 在 2K · 1/32 错、其余三个设置对。按格子预测 B 的完整匹配：T1-2K 2 / 12（1/32）与 4 / 12（1/8）；T1-8K 4 / 12 与 4 / 12（以 A 在该格可用为前提）。T2 需要两条记录都在窗口内，而每对至少一条在 front 或 middle，所以 **T2 的 B 预测 0–1 / 12**（所有设置）。B 错时的回答形态：仍给出一个四位数（格式错误 ≤ 1 份），其值预计多来自窗口内的近期记录，或者是与编号数字重合的编造数。

**预测 3：C（均匀随机）接近零。** 每层每组在候选域里均匀抽 k 个位置，单个位置被抽中的概率是 k / M：2K 为 64 / 1982 = 3.2% 与 256 / 1982 = 12.9%，8K 为 3.1% 与 12.5%。被查询记录的 12 个 token 在同一层同一组里被整条抽中的概率在 1/32 下约 1e-6，在 1/8 下也不足 1e-4；而值由 4 个数字 token 构成，缺一不可。因此预测 C 的完整匹配在每个格子里 **0 / 12（1/32）、0–2 / 12（1/8）**，把握八成；错误以编造数为主。C 对目标片段的覆盖率（每步每层每组读到的目标 token 数 / 目标 token 数，取平均）预测落在 k / M ± 0.5 个百分点内，这是结构性数字，不是学习结果。替代解释（两成）：资料经完整读取 Prefill 后，记录后面的换行 token 或后续位置的深层 KV 已汇合了该记录的值，模型能从非目标位置间接取回——若出现 C 在 1/8 下 ≥ 3 / 12 的格子，就要检查这些样本的覆盖率是否仍接近 k / M。

**预测 4：D0（未训练索引）不优于 C。** 随机投影打分是由内容决定的确定性选择，但权重未训练；在这种重复格式的表里，预计它偏向选同类 token（数字或"编号"），形成成簇名单而非覆盖目标。主预测（六成）：D0 的完整匹配与 C 同量级（每格 0–2 / 12），覆盖率均值与 k / M 同量级但逐层方差更大；替代一（两成半）：D0 比 C 差，因为成簇选择把名额浪费在重复 token 上；替代二（一成半）：D0 在 1/8 下偶然更好（≥ 3 / 12）。D0 的每层名单会被保存，用来核对"成簇"这一说法。

**预测 5：三类同题分歧案例。** "A 对 B 错"大量存在（front / middle 目标），移近后变对的比例 ≥ 3 / 4（移位改写只在 A 仍对的样本上判断）。"A 对 C 或 D0 错"几乎处处存在，关联记录将显示被查询记录的 token 在绝大多数层组里没有被选中（覆盖率 ≈ k / M）。"四种方法都对"预计不存在或 ≤ 2 份；若出现，预期是 C / D0 在若干层里恰好选中了值的数字 token（该样本的逐层覆盖率高于 k / M），而不是靠 F。

**预测 6：反事实。** A：改被查询记录的值后答案跟着改（A 原本答对的样本中 ≥ 90%）；改无关记录后答案不变（≥ 90%）。B：目标在窗口外时，改值后回答**不变**（它根本没读到），这是窗口基线的签名，预计在全部窗口外改值样本上成立；目标在窗口内时跟着改。C：选择与内容无关，改无关记录时若该记录未被任何层组选中，输出差异只来自 Prefill 后续位置的 KV 变化，预计回答在 ≥ 70% 的样本上不变；D0 的选择由内容决定，改一条记录可能改变名单，预计不变比例更低（≥ 50%）。两种改写都重建前缀，不复用 KV。

**预测 7：成本。** 前缀 Prefill 2K 约 0.4–0.7 s，8K 约 1.7–2.2 s（G1b 测得 8K 约 1.75 s，这里前缀略长且含索引表构建）。解码每步 A 约 11–14 ms，B / C / D0 与 A 同量级到 +30%（小算子链、CPU 侧随机抽样、覆盖率记账都在请求计时内）。第一遍（A，48 份）约 2–4 分钟；第二遍（可用格子上 A + 3 方法 × 2 档 ρ）约 10–20 分钟；改写约 3–6 分钟；总设备时间 ≤ 40 分钟，远低于 2 小时上限。分配内存峰值 < 8 GB。若第一遍超过 20 分钟，第二遍把 8K 每格减到 6 份（B、C、D0 与 A 同减）并记录。

**不能推出什么（预先声明）。** 48 份是探索样本；本卡不做区间统计，不支持"损失小于 2 个百分点"或其反面；D0 未训练，它的成绩不代表训练后的索引读取；B 的成绩由窗口几何决定，不代表任何学习效果；全部结论限于 Qwen3-0.6B、bf16、MPS、本任务格式。
