实验课 07：训练后的稀疏模型，答对了多少，实际花了多少？¶

这次让各方法真正独立回答 32 份新资料：模型先完整处理一份约 2K token 的记录表，再回答指定编号对应的四位值。这个任务称为 T1。Qwen3-0.6B 主体和索引参数都固定；五种方法同题作答，共保存 160 条原回答。

资料缓存建立时还没有问题。从问题第一个 token 起，各方法读取自己的历史、写入自己算出的新 K/V；生成时把自己选出的 token 送回模型。 它们不借用完整路径后来算出的状态。

2. 先看原回答，再解释分数¶

各路径独立维护问题与生成状态。少读方法共享 F 和候选名额；D0/D 索引均为 fp32，主体为 bf16，均采用同一原位置排序规则。

本课冻结评分取回答最前面的一个独立四位数，与目标完整匹配。若先复述编号再给正确值，仍记错；解析出问题编号称编号回声，数值数量不足称格式不足，达到生成上限称截断，属性可重叠。含特殊 token 的原文另存。

def score_answer(task: str, targets, text: str, *, truncated: bool) -> dict:
    """Exact match = the first len(targets) standalone four-digit numbers equal the targets in order.

    Also reported: per-item correctness, whether every target appears anywhere (any order), whether a two-item answer is
    exactly the targets swapped, format_error (fewer numbers than required) and the truncation flag passed by the caller.
    """
    targets = [str(t) for t in targets]
    need = len(targets)
    if (task == "T1" and need != 1) or (task == "T2" and need != 2):
        raise ValueError(f"{task} expects {1 if task == 'T1' else 2} target(s), got {need}")
    numbers = extract_numbers(text)
    predicted = numbers[:need]
    return {
        "numbers": numbers,
        "predicted": predicted,
        "exact_match": predicted == targets,
        "item_correct": [i < len(predicted) and predicted[i] == t for i, t in enumerate(targets)],
        "targets_present_any_order": all(t in numbers for t in targets),
        "order_swapped": need == 2 and len(predicted) == 2 and predicted == list(reversed(targets)),
        "format_error": len(numbers) < need,
        "truncated": bool(truncated),
        "text": clean_text(text),
    }

5. 同一个名额，为什么会出现三个读取比例？¶

以下数量都按本步某一层、某一个 KV 组计算。沿用上一节的真实案例 G4lite-T1-2K-00：资料前缀有 2,008 个 token，问题和模板尾部共 35 个。输入第一个问题 token 后，可读位置有 2,009 个；本次请求的额外名额取 round(2009/8)=251，随后固定。这就是配置 ρ=1/8 的使用位置。

处理完问题和模板尾部、准备预测首个答案时，可读位置已增加到 2,043 个。其中首 4 个和最近 64 个共 68 个必留，代码记作 F；剩下 1,975 个候选位置。少读方法再从候选中选 251 个，因此：

  • 名额参数：1/8 = 12.5%，用于请求开始时算出 251。
  • 候选抽取比例：251/1,975 ≈ 12.71%，表示从本步候选中取了多少。
  • 总读取比例：(68+251)/2,043 ≈ 15.61%，表示这一层、这一 KV 组的主注意力使用了多少合法位置。

表中的符号只是这几个对象的简称：N 为本步合法位置数，M 为去掉必留位置后的候选数，k 为实际选中的候选数。不能把“ρ=1/8”说成“主注意力只读全部历史的 12.5%”。 319 也不是整个模型所有层、所有组名单合并后的不同位置总数；各层组可以选中不同位置。回答继续生成时，名额仍是 251，最近 64 个位置及其他入选位置可以变化，两个实际比例的分母也继续增长。

下表汇总 32 份资料在首个答案预测处的实际范围。A 读齐全部历史，没有候选配额；空值不表示它不读取。

每步用完一份名单，也不会删除其他位置的 K/V：下一个查询可能选中不同位置。完整 K/V 因而继续保留，D0/D 另外保存索引键 z。make_trained_state 建立这两类缓存，FrozenBank 持有各层固定索引参数。

当前额外存储量可以直接按配置核算：每层、每组、每位置的索引 z 用 32×4 字节，主 K+V 用 2×128×2 字节，所以索引缓存占主 K/V 缓存的 25%。它对应表中 A 约 231.4 MiB、D 约 289.3 MiB 的数组分配量，不能解释成整个进程内存增长 25%。

6. 答得短，不自动代表算得快¶

答题时，模型自己的输出决定下一次输入；计时时，下一次输入已经给定。 本课分开运行这两种循环：

成本序列由 A 事先产生，所有方法输入同一串，即使中途含 EOS 也继续。这样比较的是同样 32 次前向，不会把少生成几个 token 算成提速；这些控制输出不参与评分。处理完问题及聊天模板后缀的最后一个 token 时已经预测了首个答案，计时表里的 32 次是随后另外执行的前向。

问题怎样输入也影响成本。 表中的 A（A-step）把已知问题逐 token 输入，与少读方法对齐；A-best 一次输入整个已知问题，再逐 token 输入那串相同的控制序列。两者都完整读取历史，只是已知问题的处理方式不同。

使用 4 份预定资料，每方法预热 1 轮、计量 3 轮，轮换方法顺序。模型和分配器已经常驻，新缓存请求不含首次加载模型。“配对控制前向/A”先对同资料同轮次算比值，再取中位；不能用两个总体中位数相除替代。

资源/预算检查、日志、计分和输入搬运在计时外，阶段前后同步；D/D0 内部参数与缓存身份检查仍在计时内，未单独分离其成本。KV+z MiB 只数主缓存与索引数组；RSS/MPS 是进程或后端的采样值，不当作某方法峰值。

7. 本轮结果支持什么？¶

任务收益已经出现。 同一批新 T1 上，D0 为 0/32、D 为 17/32；读取结构、名额、精度和排序规则相同，索引参数经过训练后确实改善了本批独立生成。但 D 只保留 A 原本正确的 15/21 题，没有完全保住完整读取表现。

成本收益没有出现。 等工作量的 32 次控制前向中，逐资料逐轮配对 D/A 的中位数为 1.579，约慢 58%；保留完整 K/V 后还增加了索引缓存。当前记录没有将全部耗时差分解到单一操作。

这份证据限于 Qwen3-0.6B、约 2K、同一种资料生成器/提示、一个训练种子，并且资料 Prefill 完整。第五课的教师覆盖、第六课的状态误差和本课正确率各回答不同问题，不能相互换算；未执行从资料开始稀疏或额外轨迹修正训练。

末格旧 G3a 账是第四课单层训练，共享账累计第五至七课。研究交付已完成，这里保存实际得失，不因还有预算就追加实验。
