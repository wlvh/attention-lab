# 当前有效方案 · v3 + 评审补丁 + Mac-first

整理日期：2026-10-16。**这是执行规格，不是实验结果。** 原始v3保留在 [archive/PLAN_v3.md](archive/PLAN_v3.md)。本文件明确合入后续讨论的修订，不无声改写原文。详细变更见 [DECISIONS.md](DECISIONS.md)。

## 1. 目标与非目标

同一份主体权重、任务、设备和生成规则下，比较完整读取与索引筛选的速度、质量、内存和额外学习成本，找出成立区间与失败原因。

分别报告：实现正确性、冻结主体的改造效果、尚未研究的充分训练架构上限。负结果与证据不足均可交付。不从局部算子推整模型，不从热读取推冷请求，不从Mac结果推CUDA结果。

首版不做从零预训练、几十B主体、主体更新、多卡、MoE、推测解码、量化、推理服务和网页应用。

## 2. 设备与软件

MacBook Pro M4 Max / 128GB 是用户提供的信息，作为首选机器，实际系统与能力由G0采集。原生Apple Silicon Python，项目虚拟环境，PyTorch MPS；CPU只承担小规模双精度参照和读取报告。FP32先验证，低精度逐项预检后使用；不是预先保证MPS BF16、编译或GQA融合支持。

Windows RTX 4080暂不配置。16GB主存和显存另行实查。CUDA是独立复核轨道，不拿两台设备的不同策略直接求架构加速比。

先不锁一个未经本机验证的库版本；G0选择官方可用组合，通过运算预检后记录精确依赖与源码版本。从第一次正式比较起冻结环境，升级意味着重新跑受影响测试。

性能可行组合和质量可行组合必须求交集。0.6B快但不会做、4B会做但不快，不能拼成一个有效方案。

## 4. 读取策略与预算

A读取全部合法位置。B按与稀疏路径相同的总名额读取最近位置。C保留首部与近期，其他均匀随机。D用小索引器选择较早历史。D0为未训练索引诊断；R为完整打分后按教师分配选位置的昂贵诊断，不计入廉价加速曲线，不叫质量上界。

F为首4个位置与最近64个位置的并集，包含本步已产生的新KV；不足时去重。C/D/R在候选域（合法历史减F）中额外选择k。

请求起始合法长度N0决定固定名额：k0=min(round(ρN0), 候选域起始大小)。ρ先测1/32与1/8，1/128只在有依据时加；请求内固定k0，后续按合法范围取min，实际保留比例随步记录。新实验不要同时改变k规则。全选退化归正确性，不作为稀疏加速证据。

窗口B只保留最近同等数量，不另强制首4；这一差异是基线定义，不归因于学习效果。C与D具有完全相同的F和总名额。

## 5. 索引器

每层每KV组一对矩阵。r=32，取q_norm/k_norm后、**主RoPE前**的Q/K。组内Q拼接投影为u；单个K投影为z；u·z/√r对候选位置评分。主注意力仍对入选主K/V重新打分。

P0为索引空间不额外施加RoPE；P1在索引空间内按原始逻辑位置旋转。P0不是完全无位置信息。用G3单层校准选择，不能预写赢家。

Prefill遇到旋转前K时，分两路构建主RoPE K缓存和索引z缓存；不要直接投影普通缓存中的旋转后K。一次与分块构建z要一致。z只在参数固定后复用；训练过程中不跨更新保存陈旧z。

教师分配按组平均主头权重，排除F后重新归一化，KL直接训练连续索引分数；候选原始总质量低于1e-4的行跳过并记录。归一化前质量m_C必须保存，不能只有条件coverage。主体detach且不保留反向图；不打开全量output_attentions。

训练两个种子各≤200万教师输入token，每资料≤8条查询行；按层计算并释放。一轮实际稀疏轨迹校准≤100万token，单列。P0/P1单层先用64份资料检验。改r或查询共享结构后重新测对应性能，不沿用旧通过结论。

G1的“10%”是投资门槛，不是架构定理。Mac先跑正确普通路径，能编译则两边一起测；不能编译不伪造通过也不推翻CUDA可能性。长期MPS性能受限时，记录后再决定是否请求CUDA轨道。G1a微基准通过不等于G1b整模型通过。

G1a仅研究一层真正读取成本；模型主体瓶颈必须G1b实际检查。随机张量的分布、选择局部性与真实轨迹不同，后续需重测。

## 7. 三类任务

T1返回一条记录的四位值（≤64新token）；T2返回两条相距较远记录（≤64）；T3按给定顺序返回8条记录（≤128）。额外“所有某标签记录”只作压力报告。值每资料随机绑定，目标位置前中后平衡；不能只复制最近答案。

按完整资料分train/calibration/test，固定数据种子、生成器版本与哈希。系统→资料→问题→回答起点，整条分词后确定前缀切点。共享前缀token必须精确核对相同；聊天模板关闭thinking，生成与解析规则在校准集冻结。32份反事实改目标/改无关信息分别检查。

校准每任务/长度32份：2K、8K及性能候选长度（去重）。正式每任务/长度最多256份，ρ最多确认两档；预算不够各策略按冻结顺序共同缩减。R/D0最多24份诊断，不用测试集选赢家。

## 8. 问题与生成协议

协议命名用 `document_dense_then_sparse`，避免与位置变式P1混淆。共同资料前缀只能到问题之前。资料完整处理，D额外构建索引；从问题第一个token起，各路径独立。

保留两个完整基线：A-step与D同样逐token问题处理，定位机制；A-best成批处理已知问题，然后正常逐token生成，判断真实请求价值。D若不支持批量问题，保留此成本，不拖慢A-best。

热读取=问题处理+生成；冷请求=资料Prefill+索引构建+热读取（模型文件加载另列）；多问均摊=同资料1/4/16次，所有版本相同复用权益。顺序请求回退valid_length并覆盖后缀，不复制整条资料；真并发才隔离状态。

资料深层KV已经通过完整注意力汇合历史，这个协议不能证明从头稀疏的Prefill质量或速度。后者只在G5独立探索。

## 9. 预测与测量

`scripts/roofline.py`输出载荷情景；默认不填Mac带宽。S1索引+一次入选KV，S2加gather写与重读。两条路径访存下界之差不是耗时差上界；CPU累计提交时间不是墙钟增量。r/(2d)是同精度扫描假设下的载荷比例，不是不可突破的显存搬运下界。

Mac预测只写方向及不确定性：短上下文新增选择开销可能吞没收益；长历史通常提供更大潜在KV字节节省；编译/布局/内存层次可改变结果。没有有效带宽测量不填吞吐。原v3的CUDA数表仍在archive，不迁移成MPS结论。

正式稀疏路径先gather再主QK；教师/参照才可完整打分。A/B/C/D统一缓存实现与dtype；优化A不保留人为慢循环。计时前后同步，预热与正式计时分离，剖析另跑，不把插桩开销混入正式值。

先一小批能力预检，再5次独立进程/重点组合的计划；预热20、测50是上限起点，受本地预算约束。连续生成检查重新编译次数、同步点、工作集增长。均匀随机与成簇名单的强制诊断，不冒充学习型D的真实选择。

## 10. 质量与解释

报告逐资料完整匹配率、配对D-A、95%区间、格式失败、T3逐项正确。区间方法在冻结测试前确定；配对分歧少或为零时预先定义精确事件界或适合稀少分歧的方法，不让普通bootstrap退化的零宽区间伪装确定性。样本256并不固定对应3–4pp半宽。

每层组记录m_C、条件coverage、遗漏总质量m_C(1-c)、局部输出差、教师熵/与R的差距。均匀分配下coverage=k/M是结构限制；V相似时低coverage仍可低误差，不能要求所有层学出尖锐检索。

局部恒等式 o_full=m·o_selected+(1-m)·o_omitted 仅适用于相同Q/K/V与同一softmax参照，不自动约束整个模型。答案由多层累计变化决定。证据链是查询→选择→主读取→输出→任务→耗时。

## 11. 预算与收口

本地工作集80GB预警/100GB硬边界，默认不租云。500万教师输入token为训练总预算，所有重试也累计；本地设备活跃时间30小时为当前上限，不是完成保证。每关先小批计时校正，明显超预算就减矩阵/样本或交负结果。

云总费用≤$100，计算70、存储传输10、预留20。不写死价格。当前没有用户云凭证，没有授权启动实例；需要时提交实际设备问题与报价/停止办法，24/48GB单卡优先。参考 [BUDGET.md](BUDGET.md)。
