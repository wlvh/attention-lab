# G4-lite：新T1资料上的质量与实际成本

依赖：G3b-lite 的固定28层参数与G3c的真实推理正确性、固定上游提交；不需要上游PR先合并。

**冻结矩阵。** 32份预先登记的新约2K T1资料，A/B/C/D0/训练后D，同题同F/名额（A完整读取）。主体bf16、索引D0/D为float32，P0/r32、ρ=1/8；thinking关闭、贪心生成、最多64新token、沿用G2-lite的完整匹配/解析和编号回声分类。各方法真正独立自由生成；A答错也保留。测试开始后不改模板/解析/参数/样本，不追加训练。

**质量。** 保存逐题原始文本、token、解析、正确性/格式/回声/截断、目标位置与首生成步实际读取预算/名单。报告每方法准确率、与A配对四格、D相对D0/C变化；32份只支持小规模描述，不作总体保证。R不作为任务质量上界。局部覆盖率和局部误差作为诊断单列，不替代答案成绩。

**成本。** 自由生成的实际Prefill、问题与生成时间、生成长度、内存分别记录，标明其中包含的计分/同步开销。另用固定的最终测试索引0–3做同token序列的成本对照：A/A-best/B/C/D0/D，32个延续token、1次预热/3次测量，中位数与范围；序列来自A，不是标准答案。A-best批量处理已知问题，其他逐token；实际精度、后端、索引构建、缓存容量和复制/回退费用明确列出。冷请求=实际资料处理+问题+生成，已有缓存口径单列；不引旧微基准作为新速度结果，不把提前EOS误当加速。

**预测。** D可能比D0/C改善T1，但固定完整路径特征的学习不保证稀疏部署恢复能力；约2K处选择/索引成本可能使D更慢。任何负结果都可完成任务。首轮不通过改测试、加模型、改ρ或轨迹修正去寻找好结果。

**验收与停止。** 相关CPU契约、逐题重算、原始记录/manifest/版本/参数对应、失败案例与教学Notebook/中文HTML齐全，提交待审PR。三阶段共同新增14400秒设备预算，现金0；开始下一批前估算预算，不足则记录缺口而不伪称完成。页面无法完整预览保留未验，不阻止研究交付。三项缩减任务交齐后结束Goal，后续PR合并和研究扩展仍需用户授权。
