## 为什么有这一步

原始问题包含速度、质量、内存与训练成本四个方面。G1b 回答了速度一侧（同模型同设备下未训练索引读取的整步收益不足 10%），速度门槛是限制工程投入的门槛，不是学习价值的门槛；质量一侧——读得少时模型丢掉什么——尚未回答。本任务用 48 份探索资料和四种读取方式把这个问题落到具体案例上。

## 范围（只做这些）

- 模型：Qwen/Qwen3-0.6B，revision `c1899de289a04d12100db370d81485cdf75e47ca`，bf16，MPS，batch 1，主体冻结，索引器为 G1b 的未训练随机 GroupedIndexer（r = 32，种子登记在配置）。不训练主体或索引器，不换模型，不恢复 Metal 优化，不租云，不调用付费 API。

- 读取预算 ρ ∈ {1/32, 1/8}，请求内 k0 固定（由请求起始合法长度决定）。

**这 48 份是探索样本**，用来找有解释价值的差异与案例；不用来证明"损失小于 2 个百分点"，不做 G4 的区间统计。

## 四种读取方式

| 名称 | 读取 | 备注 |
|---|---|---|
| A | 完整读取：全部合法位置 | A-step 口径（问题逐 token 处理） |
| B | 近期窗口：F ∪ 最近的 k 个候选位置 | 名额给最近的候选位置 |
| C | 均匀随机：F ∪ 候选域内均匀抽取的 k 个位置（固定种子，每层每组独立抽取） | **不叫"随机筛选"** |
| D0 | 未训练索引：F ∪ 随机初始化 GroupedIndexer 打分的 top-k | **与 C 分开命名**：D0 的选择由内容决定但权重未训练 |

B、C、D0 在同一 ρ 档位拥有**相同的固定集合 F（首 4 加近 64）与相同的实际读取名额** `68 + k`；全选（k0 = 容量）时三者都退化为 A。契约测试先证明这三点，再跑任何资料。

**与 `docs/PLAN_CURRENT.md` §4 的一处冲突及依据。** §4 写"窗口 B 只保留最近同等数量，不另强制首 4"。本任务按用户 2026-10-17 的任务指令执行：B 与 C、D0 共用同一个 F（含首 4），名额给最近的候选位置。理由：三种方法在同一 F 与同一名额下只差"名额给谁"，对照更干净；差异只有 4 个位置，不改变窗口基线的含义。按约定优先级（用户后续明确要求 > 当前方案）记录于此，不回写 §4。

## 协议（`document_dense_then_sparse`）

1. 资料前缀（聊天模板头 + 资料正文，**不含问题**）用完整读取处理一次并建索引表；前缀切点在整条分词后确定，并逐 token 核对前缀确为完整提示的精确前缀。
2. 从问题的第一个 token 起，各方法用自己的读取策略逐 token 处理问题与模板尾部（`phase = decode`），再贪心生成；各方法的缓存是前缀缓存的独立副本，不借用他人的 KV，不喂正确答案，自由生成作为最终成绩。
3. 资料改写后重建前缀，不复用改写前的 KV。
4. 记录每个请求的 k0、实际读取数、实际 token 数、生成 token 数、是否截断、解析结果、耗时。

## 顺序与停止点

1. **先跑 A。** 每个（任务，长度）格子的完整匹配率 ≥ 80% 视为"基线可用"；80% 只是小样本可用性检查，不是质量结论。
2. 基线不足时允许**一次有记录的提示修正**（改提示措辞或格式，不扩大模型、不扩大样本、不改任务定义），修正前后的结果都保留。
3. 8K 不可用但 2K 可用 → 在 2K 研究机制；两种长度都不可用 → 交付"基线尚不适合该任务"的证据后停止。
4. 只在基线可用的格子上比较 B、C、D0（两档 ρ）。所有样本与失败保留。
5. 预算：现金 0；首轮设备运行上限 2 小时，含预检、失败与重试；先小批预检校准耗时，预计超预算时各方法成组缩减并记录，不牺牲对照公平性补满表格。

## 案例与反事实（存在才展示）

- A 对 B 错：关键记录是否在窗口外；把记录移近（移到窗口内）后答案是否变。
- A 对 C 或 D0 错：实际选中与漏掉的位置（只作关联记录，不作因果结论）。
- 四种方法都对：关键信息是否在固定集合内，或模型能否从别处获得。
- 预先选少量资料做两种改写：只改被查询记录的值（答案应跟着改）；只改一条无关记录（答案应不变）。
- 为代表案例记录每层每组真实选择的位置（一步的名单），不保存全层全位置的完整 attention 矩阵。
