# 注意力读取取舍实验方案 v3（关卡制）

**版本 2026-10-15。状态：设计稿，没有任何实测数字。** 整理自 GPT 6 Pro 的 v2 方案、Claude 的评审与 GPT 的回应。三方一致的部分直接采用，分歧处的取舍见附录 A。

---

## 0. 一页摘要

**问题。** 同一份预训练权重、同一任务、同一设备、同一生成规则下，先用小索引器从历史里选出一部分位置再做主注意力，相比完整读取历史，速度、答案质量、内存和新增训练成本各自怎样变化？收益从什么上下文长度开始出现，又在什么条件下消失？

**方法。** 五道关卡，按"最可能让项目失去价值的假设"排序。每道关卡先写预测，再测量，再决定下一关是否投入。第一关只用随机张量和随机 token 测执行路径，不生成任务数据，不训练任何参数。

**对象。** Qwen3 0.6B / 1.7B / 4B，主体权重全程冻结。新增的只有每层每个 KV 组一对小投影矩阵。四种读取策略：完整、近期窗口、随机、学习型索引；另有两个诊断状态。

**预算。** 本地 M4 Max 128GB 与 RTX 4080 16GB 为主。云端现金硬上限 100 美元，预期实际 0 到 25 美元，仅用于 4B 在 32K 上下文的显存不足时。只给第一关预先投入工时，之后每关由前一关的结果解锁。

**停止条件。** 第一关在 32K 以内、编译执行下仍看不到索引路径更快，速度主线即停止，剩余工作缩为 0.6B 上的小规模质量与教学实验，并交付剖析报告说明开销落在哪里。

## 1. 问题边界与三类结论

| 类别 | 回答什么 | 本轮能否给出 |
|---|---|---|
| 实现正确性 | 子集执行是否与完整注意力在数学上对应；缓存、遮罩、位置是否正确 | 能，关卡 1 |
| 改造效果 | 冻结主体、只加索引器时，稀疏读取带来的速度与质量变化 | 能，关卡 3 到 4 |
| 架构能力上限 | 从头训练或充分适应后，稀疏架构能达到什么水平 | 不能，范围外 |

不许从前一类推后一类。"索引路径在本设备上不划算"、"质量损失过大"、"证据不足"都是合格结论。本轮的成功标准不是"证明稀疏更快"，而是"每个结论都有预测和对照可查"。

## 2. 实验对象

### 2.1 模型梯子

| | Qwen3-0.6B | Qwen3-1.7B | Qwen3-4B |
|---|---:|---:|---:|
| 层数 | 28 | 28 | 36 |
| 查询头 / KV 头 | 16 / 8 | 16 / 8 | 32 / 8 |
| 每头维度 | 128 | 128 | 128 |
| 参数量（按配置推算） | 5.96 亿 | 17.2 亿 | 40.2 亿 |
| BF16 权重 | 1.19 GB | 3.44 GB | 8.04 GB |
| 8K 上下文完整 KV | 0.94 GB | 0.94 GB | 1.21 GB |
| 注意力占每步流量，8K / 32K | 44% / 76% | 21% / 52% | 13% / 38% |

三个模型 KV 头数和每头维度相同，KV 载荷只随层数变化，所以模型越大、注意力占每步流量的比例越低。这正是速度实验与质量实验对模型选择的要求相反的原因：速度效应在小模型上最容易观察，质量基线在大模型上最容易成立。

处理办法：**速度曲线三个模型都测，它与权重内容无关，随机 token 即可；质量主实验用通过基线门槛的最小模型；4B 只用来确认结论是否随模型增大而改变。**

参数量以运行时 `numel()` 为准。原生上下文 32,768，输入与输出合计，不启用位置扩展。

### 2.2 六种读取方式

两边都使用 KV 缓存，区别只在每一步让哪些历史位置进入主注意力。

| 代号 | 较早历史怎样处理 | 角色 |
|---|---|---|
| A 完整 | 读取全部合法历史 | 基线 |
| B 窗口 | 相同总名额下只保留最近的位置 | 无索引的确定性对照 |
| C 随机 | 固定集合之外均匀随机选 k 个 | 区分"少看"与"选得好" |
| D 索引 | 索引器为候选历史打分，选 k 个 | 主研究方案 |
| D0 未训练 | D 的结构，随机初始化参数 | 只在校准集上看训练的作用 |
| R 完整打分后选 | 先算完整注意力分配，再按它选 k 个 | 昂贵诊断，不参加速度比较 |

R 已经支付了完整打分的成本。它的作用是区分"索引器选得不够好"与"这个预算下本来就有损"，它不是质量上界。

### 2.3 读取预算

固定集合 F：最前 4 个位置加最近 64 个位置，对应教材里的近期局部窗口与注意力汇聚位。候选集合：其余合法位置。在候选集合中选 k 个，k 按比例给：

| ρ = k/N | N=512 | N=2048 | N=8192 | N=16384 | N=32768 |
|---|---:|---:|---:|---:|---:|
| 1/128 | 4 | 16 | 64 | 128 | 256 |
| 1/32 | 16 | 64 | 256 | 512 | 1024 |
| 1/8 | 64 | 256 | 1024 | 2048 | 4096 |

B、C、D 在同一 ρ 下实际读取总数相同，按去重后的数目记录。k 大于候选数时退化为全选，这类格子归入正确性测试，不进入速度结果。512 与 2048 只服务质量实验与正确性，不承担证明速度收益的任务。

### 2.4 索引器

每层每个 KV 组一个索引器。组内的多个查询头共用一张名单，主注意力仍保留各头独立打分。

**输入取 q_norm / k_norm 之后、RoPE 之前的 Q 和 K。** 对已旋转的向量再做任意线性投影，分数变成

```
score = qᵀ R(t)ᵀ Wqᵀ Wk R(s) k
```

中间的 WqᵀWk 一般不能穿过旋转矩阵，相对位置性质不再成立，索引器只能用秩 32 的容量去抑制绝对位置带来的噪声。DeepSeek V3.2 的参考实现也是让索引器从隐藏状态和低秩查询算自己的向量，再在索引向量内部施加 RoPE。

位置编码两种变式，在关卡 3 的单层实验中比较后定一种：

- **P0**：索引空间不加位置编码，纯内容匹配。
- **P1**：在 r 维索引向量内部做独立 RoPE，使用相同的位置编号。

RoPE 之前的 Q/K 并非没有位置信息，它们已经携带前面各层的结果；教师分配也不是纯内容匹配。所以 P0 与 P1 谁更好要测，不先验认定。

结构与规模：

```
u(t) = Wq · concat(本组各查询头的 Q_t)   # (heads_per_group × 128) → r
z(j) = Wk · K_j                           # 128 → r；推理时每个新位置算一次，存入索引侧表
s(t, j) = u(t) · z(j) / √r                # 只对候选集合计算
名单 = topk(s, k) ∪ F
```

r = 32。参数量：0.6B 与 1.7B 各 2,752,512；4B 为 5,898,240。索引侧表每位置每层每组 64 字节，约为 KV 的 12.5%。**这个比例是 D 在任何 k 下的读取下限**：索引器仍要扫过全部候选历史，只是每条便宜四分之三。

**为什么用 KL 而不是任务损失。** 索引器通过 top-k 的整数名单影响答案。整数下标没有普通意义的导数，答案误差不会沿这条路径自动传回索引参数。所以单独给它一个作用在连续分数上的目标：

```
p  = 完整主注意力在候选集合上的分配，按 KV 组内各头平均后重新归一化
p̂ = softmax(s) 在候选集合上的分配
L  = KL(p ‖ p̂)
```

教师的 Q/K 用 detach 取出，损失只穿过 Wq 与 Wk，不需要主体的反向图。候选集合上教师总质量低于 1e-4 的行跳过并记录比例。可微替代方案，如软 top-k、straight-through、策略梯度，不在本轮范围。

这个目标学的是"完整注意力读什么"，不是"正确答案需要什么"。KL 下降与任务质量分开报告。

### 2.5 任务与数据

程序生成、精确判分，不请大模型当裁判。每份资料随机绑定编号与值，相关记录位置在前、中、后段平衡。训练、校准、测试按完整资料包划分。

| 任务 | 模型要做什么 | 检验什么 | 输出上限 |
|---|---|---|---|
| T1 单证据 | 返回指定编号的四位值 | 能否找到远处单条信息 | 64 token |
| T2 双证据 | 按顺序返回两条相距较远记录的值 | 是否漏掉第二条必要信息 | 64 token |
| T3 分散读取 | 按给定顺序返回 8 条记录的值 | 信息需求变广、输出变长后的表现 | 128 token |

另设少量"收集所有带某标签的记录"压力题，只报告，不计入主指标。

输入排列：固定系统指令、资料、问题、回答起点。先对整条提示分词，再确定资料前缀的切点，不假设分段分词拼接等于整段分词。聊天模板关闭 thinking，贪心解码，解析与终止规则在校准集上冻结。

**反事实检查。** 在 32 份校准资料上改写被查询记录的值，答案应随之改变；改写无关记录，答案不应改变。这个检查回答"模型是否真的在读资料"，比注意力图直接。

## 3. 五道关卡

每道关卡的格式固定：目的、做什么、预先写下的预测、通过标准、不通过怎样处理、投入上限、解锁什么。

### 关卡 1：执行可行性

**目的。** 在训练任何东西之前，弄清在这台 4080 上索引路径能否比完整路径更快，从什么长度开始。

**做什么。**

*1a 单层微基准，半天到一天。* 随机张量，每层 8 个 KV 组、128 维、BF16。两条路径：完整 SDPA，记录实际后端；索引路径，含索引打分、top-k、与 F 合并、gather、子集 SDPA。N 取 8K / 16K / 32K，ρ 取 1/32 与 1/8。**必须轮换至少 36 组互不相同的 KV 张量，让工作集超过 4080 的 64 MB L2**，否则测的是片上缓存热读。重复读同一组张量的热缓存结果另列。入选位置用两种分布：均匀随机与成簇集中。

*1b 整模型解码步计时，一到两天，含封装。* 把注意力封装接到真实 Qwen3 0.6B 与 4B 上，随机 token、静态预分配缓存、valid_length 控制合法范围。测 A 与 D 的单步解码时间，eager 与 torch.compile 各一组；CUDA Graph 作为第三组，仅在适用时。这一步同时完成第 5 节的正确性契约测试。

**预先写下的预测。** 数字见第 4 节预测表。文字版：

- 4B、8K、eager：D 每步新增约 250 次小算子提交，CPU 侧新增约 3 到 4 ms；访存侧理想节省 1.3 到 1.4 ms。预测 D 慢于 A。GPU 异步执行可能覆盖部分提交开销，所以是"很可能"，不是"必然"。
- 4B、32K、编译：理想节省 5 到 6 ms，约占理想步长三成；扣除 gather 与 top-k 的实际开销后，预测仍有 10% 到 20% 的净收益。
- 0.6B、16K 及以上、编译：注意力占比超过六成，预测净收益最明显，可能超过 30%。
- eager 模式下，三个模型在任何长度上的 D 都可能不快于 A。
- GPT 提出的保守情景，即 gather 产生三份入选流量，会让 8K 的节省再减 0.1 到 0.2 ms，不改变上述方向。

**通过标准。** 编译执行下，至少有一个模型与 N ≤ 32K 的组合里，D 的单步时间比 A 低 10% 以上，且剖析确认 D 没有先算完整 QK 再 mask。

**不通过怎样处理。** 先查三件事：gather 是否被 materialize 两次、top-k 是否逐组调用、每步是否有同步点。修一轮后仍不通过，速度主线停止，项目缩为 0.6B 上的质量与教学实验，交付剖析报告。这同样是合格结论。

**投入上限。** 工时 3 天，GPU 时间 2 小时，现金 0。

**解锁。** 确定主实验长度 N*，即出现收益的最短长度，以及主实验模型集合。

### 关卡 2：基线有效性

**目的。** 找到能完成任务的最小模型，不预先指定 4B。

**做什么。** 校准集每任务每长度 32 份，长度取 2K、8K 与 N*。从 0.6B 开始跑完整注意力基线。T1 与 T2 在 N* 上完整匹配率不到 80% 再升 1.7B，再升 4B。T3 只报告不设门槛。同时做 2.5 节的反事实检查。允许在校准集上调整一次提示表达并记录。

**预测。** 0.6B 在 8K 过 T1，T2 边缘，T3 低于 60%；1.7B 过 T1 与 T2；4B 三项都过 8K，T3 在 32K 不确定。

**通过标准。** 至少一个模型在 N* 上 T1、T2 过 80%，且反事实检查中答案跟随被查询记录的改写。

**不通过怎样处理。** 保留结果，速度实验照做，质量结论标注"基线能力不足"，不换几十 B 模型。

**投入上限。** 工时 1 天，GPU 时间 2 小时。

### 关卡 3：索引可学习性

**目的。** 便宜的索引器能否学到完整注意力在候选历史上的读取分配，学到以后在真实稀疏轨迹上是否仍然有效。

**做什么。**

*3a 单层验证。* 取一个中间层，64 份资料，比较 P0 与 P1。指标：KL、top-k 覆盖的教师质量 coverage@k、与 D0 和 C 的对比。据此定下位置变式。

*3b 全层训练。* 两个种子，每种子教师输入不超过 200 万 token，每份资料最多抽 8 个问题或回答位置作为训练行。主体正常高效前向，只对选中行用 detach 的 Q/K 补算教师分布，逐层算损失、逐层释放，不开 output_attentions。AdamW，学习率 1e-3，梯度裁剪 1.0，8 份资料积累一次更新。

*3c 轨迹差异检查。* 训练时索引器看到的是完整注意力产生的 Q/K，部署后前层的筛选会改变后层的 Q/K。让 D 独立跑完整的问题处理与生成，比较其实际 Q/K 下的覆盖率与训练时的差距。允许一轮有限修正：在 D 自己产生的少量状态上补算教师分配再更新索引器，预算不超过 100 万 token，单列。

**按层按组记录覆盖率是本关的固定产出。** 它直接回答"哪些层在很小的 k 下就能覆盖绝大部分教师质量，哪些层不行"。这是本项目最有教学价值的架构观察，成本为零。部署仍统一 k，分层信息留给关卡 5。

**预测。** 检索型层的 coverage@k 在 ρ=1/32 下从随机的约 3% 升到 80% 以上；相当一部分层在候选集合上的教师分配接近均匀，这些层对 k 不敏感；P0 在查表任务上不差于 P1。

**通过标准。** 留出资料上，多数层 D 的覆盖率高于 C 和 D0；3c 中实际轨迹的覆盖率下降不超过 10 个百分点。

**不通过怎样处理。** 先看 R 与组内各头的分配是否冲突，再考虑 r=64 或每头独立的索引查询，不扩大主体。

**投入上限。** 工时 2 到 3 天，GPU 时间 2 小时。

### 关卡 4：联合取舍

**目的。** 在同一模型、同一设备上给出速度、质量、内存的完整对照。

**协议 P1。** 系统指令加资料的前缀由完整注意力处理一次；D 另对前缀 K 算一次索引侧表。从问题的第一个 token 起，A/B/C/D 各走自己的路径直到生成结束。问题 token 两边都逐个处理。多个问题复用同一前缀时，用 valid_length 回退到前缀末尾再写入新问题，不复制整条前缀；A 享有相同回退。P1 只能证明"资料已处理好之后"的读取取舍，不证明 Prefill 加速，这个限定写进报告。

**样本。** 冻结测试集每任务每长度最多 256 份，长度取 N* 与 8K，四种策略用完全相同的资料。R 与 D0 只跑 24 份诊断子集。预算不够时所有策略按预先随机顺序成组缩减。

**指标。**

- 质量：按资料包的完整匹配率；D 减 A 的差值及按资料包配对 bootstrap 的 95% 区间；T3 逐项正确率；格式失败率。256 份的区间半宽约 3 到 4 个百分点，分辨不了 2 个百分点的差异，区间横跨阈值就写"证据不足"。
- 速度：热读取，即问题处理加生成；冷请求，即前缀 Prefill 加索引构建加热读取；同资料问 1 / 4 / 16 次的均摊。主加速比取同设置下 A 与 D 的完整耗时之比。分阶段剖析另跑一次，不与正式计时混合。每个重点设置独立启动 5 次，预热 20 轮、测 50 轮，报中位数与 p95。
- 内存：权重、完整 KV、索引侧表、子集临时量、分配容量、运行峰值。KV 全部保留时不声称缓存空间下降。

**预测。** 在 N* 上，D 的 T1 损失在 2 个百分点内，T2 损失大于 T1，T3 损失最大；热读取节省接近关卡 1 的单步节省乘以生成长度；冷请求几乎无差别；均摊收益随问数增加。

**判读规则。** 质量损失不超过 2 个百分点、热读取耗时减少 10% 以上、且区间支持，记为"候选有效"。质量达标但速度不达标，记为"本设备不划算"。速度达标但质量不达标，记为"需要适应训练，本轮范围外"。

**投入上限。** 工时 2 到 3 天，GPU 时间 8 小时。4B 在 32K 若峰值超过 16 GB，租 24 或 48 GB 单卡，上限 20 小时。

### 关卡 5：分层诊断与改进，有余量才做

- 固定一层一头，验证 `o_full = m·o_S + (1−m)·o_omitted`，把覆盖率与输出误差、任务变化联系起来。
- 用关卡 3 的分层覆盖率设计分层 k 预算，在校准集上选、在测试集上确认。
- 跨层名单复用：相邻层共用一张名单，能省多少索引计算，掉多少覆盖。这直接接上教材关于跨层共享的讨论。
- P2 从资料开始稀疏：若没有真正的稀疏 Prefill 内核，只报告质量变化，并明确写"未完成可比较的 Prefill 加速实现"。

**投入上限。** 工时 2 天，GPU 时间 4 小时。

## 5. 实现要点

只列影响结论的部分。

- **封装方式。** 替换每层的 `self_attn`，复用原 q/k/v/o 投影、q_norm/k_norm、RoPE 与输出路径，不改库文件。保存只存索引参数与基座模型 revision。
- **缓存。** 静态预分配 KV 加 valid_length，两边共用；索引侧表另开。分配容量与有效载荷分别记录。多分支并存时才复制，否则用回退。
- **真正少算。** 正式稀疏路径必须 gather 后计算；密集 mask 版只作数值参照。剖析确认没有完整 QK。
- **基线不做慢。** A-perf 使用设备实际支持的最优 SDPA 后端并记录；两边都做 compile；CUDA Graph 适用时加做。验收看剖析，不看代码里有没有 `torch.compile`。
- **遮罩。** 按绝对位置显式构造；非方阵不使用 is_causal。已 gather 的子集仍要排除未写入槽。
- **正确性契约，关卡 1b 完成。** 全选等于完整；相同子集 gather 与 mask 对应；不读未来、不读空槽；原位置不重编号、不二次旋转；KV 不按查询头重复；新位置的 KV 与 z 恰好追加一次；分支间无别名写；索引参数或位置规则变化时缓存失效。
- **计时。** GPU 同步、预热、固定线程数与电源设置、记录温度异常；正式计时不插桩。
- **z 的一致性。** 训练期间参数在变，不缓存 z；部署后参数固定才复用。

## 7. 教学产出

每道关卡交一页卡片：**预测、观察、支持的解释、仍可能的替代解释、下一步只改什么。**

六个固定讲解点，由实测数据配图：

1. mask 不等于稀疏：相同数学，不同计算量。
2. 解码步的访存账：注意力占比随模型变大而下降，局部快不等于整体快。
3. top-k 不可导：为什么索引器要有自己的教师，它学的是"注意力读什么"而不是"答案需要什么"。
4. 投影与 RoPE 的顺序：为什么索引输入取旋转之前。
5. `o_full = m·o_S + (1−m)·o_omitted`：覆盖率为什么是有用诊断但不是质量保证。
6. 分层覆盖率：哪些层可以少看，这才是架构判断的起点。

三张图由真实日志生成：ρ 对准确率与延迟的曲线、分阶段耗时、被选位置示例。没有数据前不画。详细轨迹最多保留 24 个样本。

## 附录 A：相对 v2 的改动与理由

| 改动 | 理由 |
|---|---|
| 关卡顺序：先测执行路径，后集成与训练 | 最可能让项目失去价值的假设最先验证 |
| 预测表进入方案 | 方案要求别人"先预测"，自己要先做 |
| 16K / 32K 为速度必做；512 / 2K 只服务质量与正确性 | 8K 以下注意力占比太低；教材也说短历史时全算可能更划算 |
| 两边都做 compile，CUDA Graph 适用时加做 | 否则测到的是调度开销；但 compile 不是净化器，验收看剖析 |
| 模型梯子 0.6B 到 4B，不预设 4B | 速度与质量对模型大小的要求相反 |
| k 按 N 的比例给 | 消除退化格；退化格转为正确性测试 |
| 索引输入取 RoPE 前的 Q/K，P0 / P1 两变式校准 | 旋转后投影破坏相对位置结构；DeepSeek 实现亦从隐藏状态起算 |
| 分层覆盖率为固定产出 | 零成本、最有教学价值；统一 k 部署与分层诊断不冲突 |
| 多问复用用 valid_length 回退，不复制前缀 | 两边公平且更省 |
| H200 移出路径；云只为 4B 在 32K 的显存 | 没有超过 100 GB 显存的需求 |
| 工时估计进入预算，只预先投入关卡 1 | 真正的成本是实现时间 |
| 微基准必须轮换工作集超过 L2 | 单层 8K 的 KV 只有 32 MiB，会命中片上缓存 |
| 保留 GPT 的 S2 保守情景 | 结论对执行方式的敏感度要可见 |
| 预测写成"很可能"，用关卡实测替换 | 下界相减不是上界；异步执行可能覆盖提交开销 |
| 教材引用按标题不按题号 | 两份教材副本题号不一致 |
