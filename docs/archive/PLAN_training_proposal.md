# 可干预的微型 Transformer：教学、建模与成本控制方案 v1.0

状态：**设计方案，尚未实现或训练这里提出的模型。** 随包只提供配置和资源预算计算器，不包含训练好的权重，也不包含完整训练工程。

## 0. 决策摘要

建立一个离线实验室：给小模型一份每次都变化的“编号—数字代码”资料，让它按查询输出答案；观察训练如何改变参数，再在固定权重下解释信息流、验证 KV 复用、测量资源开销。

首版只保留一套约 37 万参数的模型、一个由简单到较难的任务族，以及六个教学节点。默认用已有 MacBook Pro M4 Max 128GB 单机运行；已有 RTX 4080 16GB 是整体迁移的备用设备，不是同时运行的前置要求。没有云算力、付费模型 API、付费标注或额外硬件采购。

成功不是“训练出一个会聊天的模型”，而是获得三个可以分别验收的结果：

1. **学会任务**：在新资料中取出答案，且不是背固定映射或偷看目标。
2. **解释局部机制**：完整追踪计算，并用改变输入、替换局部内部状态及对照实验检验具体解释。不能承诺解释每个神经元，也不能把热力图当成因果结论。
3. **解释成本**：同一份权重在重算、回答内 KV、跨请求前缀 KV 三条路径上满足正确性要求，并能够说明实际成本从哪里来；不要求每种优化都必然提速。

首版停止线：训练输入位置累计不超过 **2,450 万**，训练和评估等模型运行累计占用设备不超过 **12 设备小时**，先触及哪个就停止自动追加实验。12 小时是投入预算，不是完成时长预测，更不是训练成功的保证。

## 2. 任务设计：先单个数字，再四位代码

### 2.1 一份资料与两个等级

单数字等级的可读例子：

```text
[BOS] K17 4 [SEP] K03 7 [SEP] K28 2 [SEP] [Q] K03 [ANS]
```

应生成：

```text
7 [EOS]
```

四位代码等级：

```text
[BOS] K17 4 9 3 2 [SEP] K03 7 1 0 6 [SEP] K28 2 8 5 9 [SEP] [Q] K03 [ANS]
```

应生成：

```text
7 1 0 6 [EOS]
```

首版词表固定为 48 个 ID：32 个编号、10 个数字、6 个标记 PAD/BOS/SEP/Q/ANS/EOS。显示名称 K03 只是资料编号，不是注意力机制的 Key 向量；空格不是额外 token。

每份资料包含 4、8 或 16 条记录。资料内编号唯一；编号、记录顺序、查询目标和代码都由生成器按明确规则抽样。代码每位独立均匀抽取，允许不同编号恰好具有相同代码。每份资料重新生成映射，不能跨资料固定 K03→7106。

若一条记录的代码长度为 m，一份资料有 n 条记录，则完整训练序列长度为 n(m+2)+m+5，错位一位的训练输入长度为 n(m+2)+m+4。n=16、m=4 时分别为 105 和 104，不必把所有序列填到 512。

### 2.2 任务为什么适合教学

单数字先分离“找到正确记录”；四位代码再增加“按顺序多步输出”。答案由字典查找程序精确生成，无需人工或大模型打分。查询位置随机，能够按资料前部、中部、后部分开统计。

它是受控实验，不是业务产品。现实中的这种结构化查表应优先用字典或数据库；Transformer 的意义在于为训练、上下文使用和缓存推理提供可检验对象。

该任务不能代表自然语言理解、数学推理或完整长上下文能力。训练不包含不存在的编号、重复更新同一个编号或自由语言问法；这些输入不属于本版验收范围。

### 2.3 防止虚假的高分

模型接口只接收 token、位置和合法遮罩；答案、目标记录位置、字典结果只交给 loss 或评估器，不能作为隐藏输入传给模型。

按整份资料划分训练、验证和测试；同一资料的不同查询不能跨集合。训练流由固定的生成器版本、种子及样本编号重建；验证与测试使用独立流，并校验资料指纹。两个模型种子复验使用同一训练资料顺序，以便观察参数初始化的影响。

数据生成器要测试四件事：字典答案与标签一致、改目标代码必然改标签、打乱记录不改标签、换查询会读取对应记录。新组合与新映射才是主测试对象；所有 32 个编号都允许在训练中出现，不把未训练过的编号嵌入混进泛化结论。

保留字典正确答案、忽略资料的基线、复制最后一条记录的基线。单数字完全不读资料的理论最佳猜测正确率为 10%，四位独立均匀代码为 0.01%；“复制最后一条”会有额外的碰巧答对机会，实际单独统计，不混同于均匀猜测。

## 3. 模型与实现边界

| 配置 | 首版选择 | 理由 |
|---|---|---|
| 层数 | 2 | 便于逐层追踪与干预，不预先规定模型必须学出哪种机制 |
| 表示宽度 | 128 | 限制参数和调试输出量 |
| 查询头 / KV 头 | 4 / 2 | 保留教材的 GQA 主线 |
| 每头维度 | 32 | 与 128 维查询输出对应 |
| 前馈 | 128→512→128，SiLU | 两次线性变换，不加入额外门控网络 |
| 位置 | RoPE，偶奇配对，base=10000 | 对齐教材的实现风格 |
| 归一化 | 每块两个前置 RMSNorm，末尾一个 | 学习缩放参数，初值为 1；与教材对照时可固定为 1 |
| 残差 | 注意力后、前馈后各加一次 | 显式写出信息传递路径 |
| 线性偏置 / dropout | 无 / 0 | 少引入干扰变量 |
| 输入嵌入与输出层 | 不共享权重 | 有利于区分读入与输出打分的角色 |
| 训练精度 | FP32 | 首版不同时研究混合精度 |
| 训练长度上限 | 128 | 当前最长训练输入为 104 |
| 诊断长度上限 | 256 | 只用于 32 条记录的长度压力测试 |

按上述配置计算参数为 **373,376**。这个数字不是“能完成任务的最小参数量”结论，只是选定实验对象的资源账本。

### 3.1 一套模型，两种注意力执行方式

教学路径显式实现 QKᵀ、位置遮罩、softmax 和加权 V；trace 开启时仅保存选定样本、层、头的必要数组。正常训练不保存整批注意力图。

性能路径在后续阶段仅替换注意力计算函数，可调用框架 SDPA。两条路径共享同一组模型参数和外围计算，不维护两套不同模型。先检查输出与梯度对照，再将性能路径用于训练或基准。

GQA 的 K/V 若临时按查询头展开，只是当前计算的工作张量；长期缓存仍存 2 个 KV 头。临时展开的内存单独记账。

不引入 TransformerLens 作为首版依赖。其公开 patching 实现可作为定位、替换、继续前向的参考，但两个层、八个查询头的模型用简单开关和回调就能完成本版干预。

### 3.2 与 NumPy 参考对齐

先使用教材的微小配置，将同一组权重显式复制到 PyTorch；归一化缩放固定为 1，保持 RoPE 配对、softmax 缩放、SiLU、残差顺序一致。分别比较每层 K/V、中间结果和最终 logits。通过后，再采用本方案的大一点的配置和可学习归一化缩放。

CPU FP64 小张量使用 atol=1e-9、rtol=1e-7 作为初始参考容差；FP32 先使用 atol=1e-5、rtol=1e-4。容差不是所有硬件上的定理。失败时先查数据、遮罩与运算路径，并保留误差分布；不得为了让测试全绿而无说明放宽。

## 4. 训练协议

### 4.1 标签与损失

输入为资料、问题、答案拼起来的序列。位置 t 预测位置 t+1；只对答案数字和 EOS 计算交叉熵。若答案第一个 token 在原始完整序列位置 P，则 logits 的 P-1 位置负责预测它，即 [ANS] 的输出预测第一位答案。

资料与问题的位置标签设为 ignore_index。它们仍参与前向计算，答案误差仍可通过计算图反向更新参与产生资料表示与 K/V 的参数；这里没有 detach，也不复用上一训练步的 KV。

每个样本的答案位置损失先平均，再对样本平均。首版同一个 batch 使用同一种 n、m，因此无须复杂 padding、变长拼接或跨文档遮罩。输出时在完整 48-token 词表上贪心选择，不用字典、指针分支或限制只能输出数字的外部规则修饰成绩。

### 4.2 超参数与课程安排

默认 AdamW，batch=32，学习率 3e-4，betas=(0.9,0.95)，weight decay=0.01；嵌入和归一化缩放不做权重衰减，梯度范数裁剪为 1.0，前 100 步线性预热，之后先保持学习率不变。它们是实验初值，不是已验证的最优配置。

每个正式种子最多 800 万训练输入位置：

- 前 100 万：4 或 8 条记录、单数字。
- 100～200 万：4、8、16 条记录、单数字。
- 200～800 万：4、8、16 条记录；25% 单数字、75% 四位代码。

在扩大任务前，检查单数字验证表现是否已明显学会。未学会时暂停并进入故障诊断，而不是照计划机械升级任务。课程发生变化必须记录为新运行配置，不能与旧配置混报。

每新增 25 万训练输入位置，运行一次快速验证。若单数字与四位代码目标连续两次同时达到，允许提前停止；否则达到单次或全局预算上限即停止。保存按验证成绩选择的 best、last 和不超过三个教学节点权重，不每一步存大文件。

### 4.3 训练前检查

先在固定 32 个简单样本上尝试过拟合，要求训练样本的完整输出全部正确。此检查纳入 50 万调试 token 预算；失败就检查标签错位、遮罩、梯度、优化器与生成循环，不能以增大模型代替诊断。

额外做未来信息隔离测试：固定前缀，修改未来答案位置的 token，在随机权重下检查答案前位置的 logits 不随未来改变。这样可以发现训练时偷偷读到答案的问题。

### 4.4 最终任务验收

冻结两套各 2,000 份资料的测试集，分别用于单数字和四位代码。按 4、8、16 条记录尽量等量分组；按目标记录位置分前、中、后组报告。

主目标为单数字加 EOS 完整正确率≥99%，四位代码加 EOS 完整正确率≥95%；两者均为目标而非保证。输出缺 EOS、多出无关字符或长度错误均算错。另报逐位正确率及首位正确率，只用于诊断，不代替完整答案正确率。

报告每项成功数/总数和二项比例区间。两次种子结果分别列出，不只展示较好的一次；两个种子只是最低复验，不足以证明广泛统计规律。

32 条记录、固定值的反事实改写、记录顺序变化等属于压力测试，单独报告，不把所有分布变化混成一个“准确率”。长度压力表现下降不自动等于缓存实现错误。

## 5. 可解释性：从看见计算，走到检验解释

### 5.1 计算可见

选定一个样本，在训练前、学会单数字后、最终模型三个节点保存：

- token 名称、词表 ID、逻辑位置；
- 每层 Q/K/V 的形状，少量数值切片与范数；
- 允许读取的遮罩与指定查询的注意力权重；
- 注意力输出、前馈输出及残差变化；
- 完整词表 logits 中正确答案和主要竞争答案的分数。

首版一层的常见形状：Q=[B,4,T,32]；K/V=[B,2,T,32]；生成一步时 Q 的位置维度为 1，K/V 为已处理历史加本步。轨迹必须来自真实数组而非手填示意值。

### 5.2 输入反事实

选单数字样本，原资料 K03=7，构造同长度新资料 K03=2，其他 token 不动，并完整重新运行模型。问题相同，正确答案应从 7 变成 2。

对照为：同样改变另一条未被查询记录；或者只改查询编号、完整重算；或者换一个记录顺序。分别记录任务正确率和下一 token 的分数，不仅保存成功的截图。

这说明行为是否依赖当前资料；不能仅靠这一层实验确定内部使用了哪一个头。

### 5.3 内部状态替换（activation patching）

对原资料和改写资料各做一次完整前向。在改写资料运行中，用原资料运行的某一层、某一位置、某一头输出，替换对应局部状态，再继续模型计算。其余部分不动。

主要指标用首个答案 token 的原始分差：

```text
D = logit(7) - logit(2)
干预效果 = D(替换后) - D(改写资料)
```

同时展示原资料 D、改写资料 D、替换后 D 和实际生成选择，不用容易被很小分母放大的“恢复百分比”作为唯一指标。

先用 32 对独立样本探索可能路径，再在未参与选择的 128 对样本上确认。比较同样大小但与目标无关的替换、反向替换以及不同层/头。结果按两次训练种子分别呈现；不能要求不同种子的“头 1”承担相同功能。

**不得把预设故事当成验收答案。** “第一层绑定编号与数值，第二层根据查询读取”可以作为待检验假设，模型也可能使用别的或冗余路径。不起作用的干预不能直接证明该位置没有贡献。

### 5.4 与合法缓存复用的严格分界

修改历史 token 后，依赖它的后续高层状态可能也改变；只替换这条记录的 KV 不是完整重算的新资料状态。内部替换是有意构造的干预，须标注为“干预态”，不能作为生产缓存优化方案。

另外，早期信息可能已经进入后续位置的表示。删除目标位置的一份 KV 不等于删除所有关于它的信息。因此，不把“遮掉目标 KV 后仍答对”简单解释成“模型没有用到目标记录”。

首版解释验收要求：能够完整还原一个计算路径，完成至少一组有干预、有匹配对照、有独立样本确认的具体机制检验，并如实给出支持、反对或无法区分的结果。不能声称整个神经网络已完全解释。

## 6. KV 与执行实验：先数值正确，再比较成本

冻结 checkpoint 后计算实际权重的身份摘要，缓存键同时包含 token 前缀、位置规则和数值精度。训练过程不持有跨步可复用状态。

### 6.1 三条主路径

A：每生成一个 token，重新计算当前全部输入。

B：完整处理资料和问题，此后只输入刚选出的 token，使用回答内部 KV。

C：缓存完整资料前缀（直到最后一个 SEP），每个独立请求克隆该前缀，再处理 Q、编号、ANS 和答案。第一个请求/预计算的写入成本必须计入冷启动账本，克隆成本计入每次请求；只保存资料，不把前一个问题或答案接给后一个独立请求。

首版只做串行整份资料缓存；不新增服务端、LRU、共享页、异步搬运或多租户隔离。教材已有的独立页实验可以保留，但不是本版交付依赖。

### 6.2 必做对照

同一个给定 token 历史上比较完整重算、只分段但不查缓存表、命中旧缓存三种 logits；先固定历史，防止第一次分叉后两条路径吃进不同输入。随后再比较自由生成是否完成任务。

错误对照包括位置从零重启、复用错误 checkpoint、不同前文的文档 KV 强行拼接、分支更新污染原缓存。要求测试能检测到故意引入的错误；不能只证明正常路径会通过。

形状测试单独检查 query_length=1、kv_length>1，以及批量处理多个新位置的矩形遮罩。合法条件是 key_position≤query_position。初版显式构造此规则，不直接把非方阵 is_causal=True 当成带缓存偏移的正确遮罩。

### 6.3 性能实验与范围

同一设备、精度、权重及后端上，采用 4、8、16 条资料；每份资料分别连续处理 1、8、32 个独立查询。编号可以重复，但只允许资料前缀复用。分别报告首次构建和后续复用、lookup/clone、prefill、decode、总墙钟与实际处理位置数。

四位输出的速度差可能很小。若需要较长序列的执行微基准，可在固定合法 token 历史上测 32/128 个后续位置；此时只声称测量计算/缓存开销，不能把不属于训练任务的长输出称作语言能力成绩。

测量先预热，至少重复 10 次并报告中位数和范围；对异步设备正确同步。关闭 trace、绘图和逐步磁盘日志，再计时；冷启动另记。数据生成和模型加载是否计入总耗时要明确。

微型模型未提速是允许的实验结果；只有真实测量支持时才谈性能收益。不把省下位置数、KV 载荷或理论 FLOPs 比值直接写成加速倍率。

## 7. 六个教学节点与停止条件

| 节点 | 要完成什么 | 学习者先回答什么 | 继续条件 |
|---|---|---|---|
| 1：计算参照 | 原 NumPy 与 PyTorch 小配置对照 | 每层中间量从哪里来，哪些位置不能读取？ | 对照和故意错误测试通过 |
| 2：学会任务 | 32 样本过拟合，随后单数字与四位代码训练 | 哪些位置贡献 loss，梯度如何到达资料部分？ | 验证达到目标或记录预算内失败诊断 |
| 3：局部解释 | 反事实、局部替换、匹配对照与确认集 | 什么观察能区分“看起来相关”和“确有作用”？ | 每条解释有原始证据与适用范围 |
| 4：KV 复用 | A/B/C 三条执行路径 | token 已选出时，哪些 KV 还没产生？ | 数值、状态隔离与任务验收通过 |
| 5：成本边界 | 载荷预算、峰值内存、重复查询基准 | 哪些省了，哪些开销仍然存在？ | 能解释实际账本，不强求提速 |
| 6：迁移理解 | 新条件盲测与第二种子复验 | 改层内前馈/位置/前缀后，哪些状态会变？ | 先预测、后检验，并解释预测失败 |

第 2 节点的学习失败不阻断教材随机模型上的 KV 正确性教学；但不得把这种回退写成新模型已经学会任务。学习能力与执行正确性分开标记。

学习者投入建议先限定为 6 次、每次最多 60 分钟的主动审核预算。它不是掌握全部内容的时间保证。每次留下一个预测、一份结果及一个被修正的理解，不用长篇阅读记录代替实验。

## 8. 成本账本与预算闸门

### 8.1 模型固有载荷（数学核算，不是设备峰值）

| 项目 | 数量 |
|---|---:|
| 参数 | 373,376 |
| FP32 权重 | 1,493,504 字节，约 1.42 MiB |
| 参数、梯度、Adam 两份 FP32 状态合计 | 5,974,016 字节，约 5.70 MiB |
| 每个已处理 token、每个请求的 KV | 1,024 字节 |
| 单请求、128 个位置的 KV | 128 KiB |
| 32 个请求、128 个位置的 KV | 4 MiB |
| 一层一个完整分数表，B=32,Hq=4,T=128,FP32 | 8 MiB |

其中 KV=2×层数×位置数×KV头数×每头维度×字节数。训练还要保存激活和求梯度所需数据，运行还包括临时数组、分配器和驱动；不能把 5.70 MiB 当作训练峰值。

运行占用超过 8 GiB 是排查触发线，不是预期需求或已测峰值。先查是否把带梯度的 trace 一直保留、是否错误扩展到巨长序列等，不先采购硬件。产物储存先控制在 1 GiB 内；最多保留 32 个完整轨迹样本。

### 8.2 训练支出上限

| 类别 | 训练输入位置预算 |
|---|---:|
| 数值验证后的训练调试与过拟合 | 50 万 |
| 主模型第一个种子 | 最多 800 万 |
| 冻结设计后的第二个种子 | 最多 800 万 |
| 一次有诊断依据的重试 | 最多 800 万 |
| 合计上限 | 2,450 万 |

这里数的是每次真正进入训练 forward 的非 padding 位置，含作为输入的正确答案部分，不只数参与 loss 的答案 token。反复看同一个样本也计入。验证/干预的 forward 位置另记账，且所有模型运行都受 12 设备小时累计上限约束。

先在最长训练 batch 上预热并实测 100 个完整更新步，记录数据生成、forward、backward、optimizer、同步后的耗时和实际位置数。正式训练剩余设备小时用下式估算：

```text
剩余训练小时 = 剩余训练输入位置 / 实测完整训练位置吞吐 / 3600
剩余项目小时 = 剩余训练小时 + 验证、解释和基准的预算
```

不能用推理 token/s 或硬件宣传峰值代替训练吞吐。100 步测量也计入预算，不能把启动与失败成本藏掉。若预算无法容纳计划，缩小实验数量或在现有设备之间整体迁移，不自动租云、不无限扩大上限。

### 8.3 钱与人工

本地方案的新增硬件、API、数据和云租用默认均为 0；不是说整个项目没有成本。已有订阅、折旧、审核和调试要另列。

电费可按额外平均功率×占用小时×当地电价计算。只作场景演示：额外平均功率 0.1～0.5 kW、电价 0.6～1.2 元/kWh、占用 12 小时，则约为 0.72～7.2 元。这些不是设备实测功率，也不是用户所在地的电价。

对本项目最应控制的成本是反复重写和没有问题驱动的调参：不建立超参数网格；第一个模型失败先找错误类别；最多批准一次写清假设的重试；没有新证据不增加层数或升级到原先约 300 万参数方案。

### 8.4 常见失败的处理

| 现象 | 先检查 | 不应立即做什么 |
|---|---|---|
| 32 样本也学不会 | 标签错位、未来遮罩、梯度、参数更新、生成起点 | 直接扩大模型 |
| 训练高分、验证低分 | 资料划分、固定映射、生成器漏洞 | 展示训练集截图宣称学会 |
| 首位好、后续位差 | 输出顺序、EOS、teacher forcing 与自由生成差异 | 把逐位准确率当完整正确率 |
| 热力图清晰、干预不支持 | 多路径、替换范围、对照、分布变化 | 强行给某个头命名并下结论 |
| 缓存与重算不同 | 历史位置、矩形遮罩、身份、状态别名 | 先放宽容差 |
| 缓存没有提速 | 模型/输入规模、复制、调度、计时方式 | 为“做出加速”而隐去开销 |

## 9. 工程交付与 AI 分工

建议的核心文件控制在少量直观模块：data.py、model.py、train.py、decode.py、experiments.py、report.py，再加 tests。配置、原始结果与文档不算另一套框架。

每次运行写 manifest：代码提交或文件摘要、配置、数据生成器版本、数据种子、模型种子、权重摘要、设备、依赖版本、精度、已消耗位置、已消耗时间以及停止原因。原始输出含逐题答案、词表分差、缓存长度与处理位置账本。

最终报告用固定模板从原始结果生成，保留正确率、训练曲线、单样本轨迹、干预对照和成本表。不开发交互式前端，不靠人工填入漂亮指标。先用 report.md 或一个简单离线 report.html 即可。

AI 可以写代码、运行测试、整理数值；学习者负责选择要区分的解释、运行前写预测、审查结果是否足以支撑结论。审核代理先查原始数组、单测和记录，再读结论。失败结果必须保留，不能自动扩大预算，也不能把干预结果改写成肯定预设故事。

## 10. 首版明确不做，以及后续顺序

不做自然语言预训练、聊天界面、RAG、MoE 训练、YOCO/线性注意力复现、分布式、推理服务、多租户、持久化缓存、生产 GPU 内核或同时迁移多种框架。

首版结束后只选一个新问题。预算最省的下一步是固定权重，利用教材已有量化代码研究 KV 压缩的数值/任务代价；之后才考虑重新训练 MHA/GQA/MQA 对照。推测解码先做确定性核验与回退微实验，不必为了验证算法先训练第二个大模型；评测随机采样或实际加速再另定范围。

MoE 不能为了“覆盖知识点”硬塞进查表任务。若任务并不需要更多参数容量，MoE 没有优势是正常结果，不适合作为首版成败标准。

## 11. 当前交付包怎么使用

- PLAN.md：完整方案。
- lab_config.json：建议配置和预算，不是已执行训练参数记录。
- estimate_budget.py：标准库预算计算器；不依赖 PyTorch，也不训练模型。
- estimated_resources.json、design_budget.json：按配置推算的参数与字节账本，不是运行测量。

直接运行：

```bash
python estimate_budget.py --config lab_config.json
```

实际测完完整训练吞吐后，填写自己的数值：

```bash
python estimate_budget.py --config lab_config.json \
  --positions-per-second YOUR_MEASURED_TRAINING_RATE \
  --extra-hours YOUR_EVALUATION_AND_ANALYSIS_BUDGET \
  --extra-watts YOUR_MEASURED_EXTRA_POWER \
  --yuan-per-kwh YOUR_ACTUAL_ELECTRICITY_PRICE
```

大写字段是待填参数，不是可以原样运行的数值。未提供实测吞吐时，计算器不会编造训练时长；未提供功率、电价时，也不会编造电费。其公式与非法维度检测已在本次会话中检查，模型收敛与 GPU 性能未在本次会话中测试。
