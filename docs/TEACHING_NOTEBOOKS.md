# Notebook 与 HTML：可重放的实验课

## 目的

Codex负责执行，用户事后按计算问题逐段理解。讲解单位是一条机制，不是随意十行代码。Notebook并非正式训练入口，也不维护另一套简化attention。

## 两个模式

默认阅读：展示当前报告对应源码、加载已存在的精简run数据、运行小规模CPU反例。不安装包、不下载权重、不训练、不自动租云。若结果不存在，显示未执行并指向脚本入口，不能用示例数字填洞。

主动重放：用户明确选择run与样本后，调用同一正式实现；长基准和训练用独立py脚本，不由Run All隐式触发。

## 每段固定结构

### 读者熟悉 Transformer，只缺本项目语境

读者熟悉 Transformer 与常规张量计算。首次解释的对象是本报告自己引入的名称、约定和实验条件，不是所有专业词汇。不要插入 Q/K/V、token、softmax、算子、内核、stride、dtype、CPU/GPU 等基础定义，也不要以逐项翻译日志字段代替机制讲解。

- 每课先交代实验怎样准备输入、依次做什么、输出拿来比较什么，再给出阶段编号、方法、任务和配置代号。不能用“G0=基础操作测量、G1a=单层注意力对照”这样的另一层名称代替实验过程；同一代号随阶段改变含义时明确注明，例如早期 D 未训练、后期 D 为训练后参数。
- 先说具体对象和操作，避免悬空的“子集”“路径”“轮换”。例如“从每个 KV 组的 32768 个历史位置中，按已给定名单取 1024 行完整 K/V”，再列形状和代码。
- 实验条件要落到执行事实：预分配多少套数组、各多大、按什么次序访问、哪些工作计时、最后除以什么。不能只把“36层轮换”换成“轮流读36组模拟层”。区分模型 KV 数组与硬件缓存。
- 只解释本项目选择的指标口径：覆盖数的是位置还是权重、分母是什么、在哪个步骤与投影前后比较、如何跨查询/资料平均；不重复讲 KL、L2、梯度等通用定义。
- 源码/版本核验继续保留，但正文只交代它对本次结果的作用。预测卡片等项目材料用一句话说明用途，不让管理术语和通用工具介绍占据学习主线。
- 第一次进入新实验时，读者应能回答：输入是直接构造的数组、随机 token 还是真实任务文字？缓存怎样产生？哪些参数更新？后续 token 来自模型还是预存序列？比较的是局部向量还是最终回答？只补与本段有关的事实，不把这张检查单塞进每节正文。
- 每段新增说明必须回答读者此处的具体疑问；用形状、数量、代码或实际输入输出消除歧义。解释不足时补具体事实，不用更多词汇表。
- 原始预测与结果保留；不要求读者先预测或答题才继续工作。说明文字修订同步导出 HTML，已有代码和输出未变时直接保留执行记录，不为文字调整重跑模型。

### 机制讲解顺序

1. 先说明模型在本段接收什么、计算什么、保存什么、怎样进入下一步，再将原预测与观察放在一起。不得要求读者先背变量表或回答预测题。
2. 展示对应commit中的正式函数（建议每格10–30行以内；长函数按逻辑拆讲，引用不能偷换版本）。
3. 写清输入输出形状与原逻辑位置；必要时显示少量数值。
4. 调用正式函数的小例子或加载正式run记录。
5. 做等价/反例检查；一次只改变一个条件。
6. 解释真实观察、不能推出什么、下一步怎样验证。

## 版本与证据对应

历史性能、质量数字必须对应运行清单中的源码版本。展示这些实验的实现时从已保存快照读取并核对哈希，不能默默打印后来加入训练参数、排序或其他修复的当前函数，再称它产生了旧结果。

CPU 例子有两种用途：若复现历史算法，就调用相应版本；若检查当前实现的契约，则明确标注“当前 CPU 检查”，提供当前 `.py` 入口，不把它冒充历史模型运行。读保存数据与运行当前小例子必须分开标识。

正文中的统计值回到逐题或逐轮记录核对，明确资料/请求/步骤/层组的单位及聚合顺序。观察、粗估和因果解释分开；没有隔离成本的实验，不能仅凭算子数量、内存快照或跨实验相减宣布已定位原因。原始预测与运行记录保持原样，课程对历史解释的更正注明依据。

## 现有课程

00 为导读，01—07 已有 Notebook 和保存输出的 HTML。前两课对应基础测量/单层注意力与真实模型接入；第三课比较未训练读取方法的质量；第四至七课依次展示单层训练、各层训练、真实状态和新题质量成本。完整目录见 `../notebooks/README.md`。已有实验不因课程修订而重新启动。

图按每课的阅读顺序统一编号为“图 课号-序号”，例如图 3-1、图 3-2。SVG 机制图、实测图和折叠案例中的图共用同一序列；一张包含多个子图的组合图使用一个图号。SVG 原图标题、Notebook 图注和 HTML 图注保持一致；结果图的图注由展示代码输出，重新执行后仍保留编号，不改图内数据或曲线。

图片连同图注占所在正文区域宽度的 50%，居中显示，保持原长宽比；SVG、结果图和折叠案例统一使用此规则，不设置像素最小宽度。原图分辨率保留。结果图使用 `scripts/teaching_display.py::show_figure` 输出，以保持 Notebook 与 HTML 的展示一致。

## 输出检查

```bash
python -m jupyter nbconvert --to notebook --execute --inplace notebooks/01_environment_and_attention.ipynb
python -m jupyter nbconvert --to html notebooks/01_environment_and_attention.ipynb --output-dir reports
```

代码或执行依赖改变时，从新内核执行受影响课程再导出；纯正文修改可保留已验证输出并重新导出，同时检查数值和图像未变。

在全新内核从上到下跑通，保留实际输出；HTML检查中文、代码、表格与图片无截断。图仅从测量记录生成；无实测性能前不画预测为实际曲线。小数学例子的数值要标“教学算例”。

GPU长实验日志不直接整段塞进输出，引用run路径及sha256。重模型不驻留读者的默认阅读内核。读取本地HTML不需要启动GPU或云服务。

长检查表、完整位置名单和重复案例用 `scripts/teaching_display.py` 的 `details` 保存在可展开区；主文保留关键对照与实际算法源码。`presentation-only` 标签只用于加载、排表或绘图的辅助单元，Notebook 中仍保留这些源代码，HTML 导出时隐藏其输入，不删除输出。算法示例与实际计算源码保持可见。导出命令增加：

```bash
python -m jupyter nbconvert --to html notebooks/02_qwen_integration_and_decode.ipynb --output-dir reports \
  --TagRemovePreprocessor.enabled=True \
  --TagRemovePreprocessor.remove_input_tags='{"presentation-only"}'
```

历史卡片的预测原文保留；当事后解释被后续核对收窄时，在附近追加带日期的更正，将旧解释明确标为历史。阶段“下一步”和“待审”都要注明当时的时点，不用旧停止状态描述当前项目。

官方执行机制参考 [SOURCES.md](SOURCES.md) 中Jupyter/nbconvert来源；具体工程约定是本项目设计。
