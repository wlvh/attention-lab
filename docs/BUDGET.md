# 资源与费用边界

## 用户硬约束

Mac本地优先；Windows 4080暂作备用。用户允许计算需求超过100GB时考虑云服务，但云总现金支出不超过100美元。当前没有创建任何云实例，也没有授权在初始化仓库时开始付费计算。

本地总内存与GPU可分配内存分别记录。工作集80GB预警、100GB硬边界（十进制），实际OS安全限制若更低就用更低值。不把内存预算当利用率目标。

## 最省成本的顺序

先标准库预测与小CPU测试→MPS关键运算→单层微基准→最小模型→有可行组合才训索引。主体前向、教师重算、失败重试、编译和评测都计入设备时间，不只算参数更新。

训练两个种子各200万教师输入token，实际轨迹校准最多100万，总计500万。默认累计本地活跃设备时间30小时为停止上限；这是资源约束，不是完成时间保证。历史v3的工日/GPU小时仅是作者估计，先用本机G0/G1实测校正，不把它们当承诺。

## 云账户总账

| 科目 | 最大预留 |
|---|---:|
| 计算（下载、安装、闲置、失败、重跑均包含） | $70 |
| 存储、传输及其他已知费用 | $10 |
| 税费、尾单和清理误差缓冲 | $20 |
| 总现金硬上限 | $100 |

没有实时可锁定报价时不估算“还可跑多少小时”。本包不复制旧报价为今天的价格。每次实际租机先记录供应商、地区、型号、RAM/VRAM、计价、税费、磁盘、流量、最短计费单位和总租时。

已花费+已产生未出账+已承诺剩余租期+存储/传输+缓冲必须一起算。预算工具是算账，不是供应商限额控制。

需要CPU RAM>100GB不等于需要GPU VRAM>100GB。先排查全量attention、全量logits、重复cache和反向图，再决定设备。现范围优先24/48GB单卡，H200、多卡不在默认路径。

## 停止机制

只有批准具体租机后才执行。单实例，关闭自动充值，设置并实际验证独立于训练进程的最长存活时间/销毁机制。$60暂停新大批次，$75导出核账，预计达到$80清理实例与独立卷；预留$20不再开新实验。

程序结束、SSH断开、账户余额低都不是可信停止策略。导出结果校验hash→销毁实例→检查附加盘/对象存储等是否继续收费→核实账单。无法验证停止机制就不无人值守运行。

## 本地成本也记录

设备占用、失败/编译次数、下载量、人工审核与Codex交互消耗。已有订阅不因本项目变为零成本，也不自动调用公司API。本轮不进行大范围超参数搜索；一关失败修一轮仍失败，交付失败机制而非继续放大模型。
